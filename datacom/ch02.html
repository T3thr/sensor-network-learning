สถาปัตยกรรมแบบลำดับชั้นและโมเดลเครือข่าย (Network Models)

การศึกษาหลักการแบ่งชั้นหน้าที่ทางวิศวกรรม (Layered Architecture), ศึกสงครามโปรโตคอลระหว่าง OSI 7 เลเยอร์ และ TCP/IP, กลไกการห่อหุ้มข้อมูล (Encapsulation/Decapsulation), และลำดับชั้นแอดเดรส 4 ระดับพร้อมการจัดการในเคอร์เนลระบบปฏิบัติการ
1. The Origin & Engineering Genesis

วิกฤตซอฟต์แวร์เสาหินและกำเนิดการแบ่งชั้นหน้าที่ (The Monolithic Crisis & Protocol Wars)

ในช่วงปลายทศวรรษที่ 1960 เมื่อโครงการเครือข่ายคอมพิวเตอร์สลับแพ็กเก็ตชุดแรกของโลกอย่าง ARPANET ถือกำเนิดขึ้น ซอฟต์แวร์สื่อสารในยุคแรกเริ่มถูกพัฒนาในลักษณะ สถาปัตยกรรมเสาหินก้อนเดียว (Monolithic Architecture) ภายใต้โพรโทคอลควบคุมเครือข่ายดั้งเดิมคือ NCP (Network Control Program ตาม RFC 33 ในปี 1970) โค้ดทั้งหมดตั้งแต่ตรรกะของแอปพลิเคชัน (เช่น การถ่ายโอนไฟล์หรือเทอร์มินัลเสมือน), การจัดลำดับแพ็กเก็ต, การควบคุมอัตราการไหล, ตลอดจนการสั่งงานบิตควบคุมรีจิสเตอร์ของฮาร์ดแวร์โมเด็มและสายโทรศัพท์ ถูกเขียนหลอมรวมอยู่ภายในฟังก์ชันเดียวกันแบบผูกพันแน่นหนา (Tight Coupling)

ความพินาศทางวิศวกรรมเกิดขึ้นทันทีเมื่อเทคโนโลยีทางกายภาพเริ่มพัฒนาขึ้นอย่างก้าวกระโดด เมื่อวิศวกรต้องการเปลี่ยนตัวกลางจากสายสัญญาณเช่าโทรศัพท์ 56 kbps ไปเป็นลิงก์สัญญาณดาวเทียม (Satellite Link) หรือเครือข่ายวิทยุแพ็กเก็ต (Packet Radio Network) บรรดาโปรแกรมเมอร์จะต้องรื้อแก้ไขซอฟต์แวร์แอปพลิเคชันใหม่ทั้งหมด เพราะระบบไม่มีการแยกชั้นเชิงนามธรรม (Abstraction Layer) ยิ่งไปกว่านั้น บริษัทยักษ์ใหญ่ด้านคอมพิวเตอร์ในยุคนั้นต่างสร้างระบบสื่อสารเอกสิทธิ์เฉพาะตัว (Proprietary Lock-in) ขึ้นเพื่อผูกขาดลูกค้า เช่น IBM เปิดตัวสถาปัตยกรรม SNA (Systems Network Architecture) ในปี 1974, Digital Equipment Corporation (DEC) สร้าง DECnet ในปี 1975, และ Xerox พัฒนา XNS (Xerox Network Systems) คอมพิวเตอร์ของ IBM ไม่สามารถสื่อสารกับเครื่องของ DEC ได้หากปราศจากกล่องแปลงสัญญาณฮาร์ดแวร์ราคาแพงมหาศาล สภาพการณ์นี้ก่อให้เกิด "สภาวะหอคอยบาเบล (Tower of Babel)" แห่งยุคดิจิทัล

กฎทองแห่งการออกแบบวิศวกรรมระบบ (Modularity, Abstraction & Information Hiding):
เพื่อแก้ปัญหาวิกฤตความซับซ้อน นักวิทยาศาสตร์คอมพิวเตอร์จึงนำหลักการแบ่งงานแบบลำดับชั้น (Layering Principle) มาบังคับใช้:
  1. ความเชื่อมแน่นสูงในแต่ละชั้น (High Cohesion): แต่ละเลเยอร์ได้รับมอบหมายภาระหน้าที่ทางวิศวกรรมอย่างจำเพาะเจาะจงและเป็นอิสระจากชั้นอื่น
  2. การซ่อนรายละเอียดภายใน (Information Hiding): แต่ละชั้นสื่อสารกับชั้นที่อยู่ติดกันผ่านอินเทอร์เฟซมาตรฐาน (Service Access Point: SAP) โดยไม่ต้องล่วงรู้ขั้นตอนวิธีหรือโครงสร้างข้อมูลภายในของเลเยอร์อื่น
  3. การผูกพันแบบหลวม (Loose Coupling): การเปลี่ยนแปลงเทคโนโลยีในชั้นใดชั้นหนึ่งจะไม่ส่งผลกระทบให้ชั้นอื่นต้องแก้ไข เช่น การเปลี่ยนสายเคเบิลทองแดงคู่บิดเกลียว Cat6 เป็นสายใยแก้วนำแสง Single-mode Fiber หรือคลื่นวิทยุ Wi-Fi จะไม่มีผลกระทบต่อเบราว์เซอร์หรือโปรโตคอล HTTP เลยแม้แต่บรรทัดเดียว

ในปี 1977 องค์การระหว่างประเทศว่าด้วยการมาตรฐาน (International Organization for Standardization: ISO) ได้จัดตั้งคณะกรรมการขึ้นเพื่อสร้างสถาปัตยกรรมเปิดที่ทุกบริษัททั่วโลกต้องปฏิบัติตาม จนกระทั่งประกาศเป็นมาตรฐาน ISO 7498 ในปี 1984 ภายใต้ชื่อ Open Systems Interconnection Reference Model (OSI Model) กำหนดให้มี 7 เลเยอร์ ทว่าในระหว่างที่คณะกรรมการ ISO กำลังประชุมถกเถียงเรื่องมาตรฐานอย่างเชื่องช้าในห้องประชุมทางการทูต กระทรวงกลาโหมสหรัฐฯ (DARPA) ภายใต้การนำของ Vinton Cerf และ Robert Kahn ได้ร่วมกันพัฒนาชุดโปรโตคอล TCP/IP ขึ้นมาใช้งานจริง และจุดเปลี่ยนสำคัญที่สุดในประวัติศาสตร์เกิดขึ้นเมื่อ Bill Joy แห่งมหาวิทยาลัยแคลิฟอร์เนีย เบิร์กลีย์ ได้นำ TCP/IP บรรจุเข้าเป็นส่วนหนึ่งของระบบปฏิบัติการ 4.2BSD UNIX ในปี 1983 พร้อมคิดค้น Berkeley Sockets API ทำให้นักวิจัยและมหาวิทยาลัยทั่วโลกได้รับซอฟต์แวร์เครือข่ายที่ใช้งานได้จริง (Running Code) ไปใช้งานฟรี

การล่มสลายของช้างสารสองตัวและปรัชญาของ IETF (The Apocalypse of the Two Elephants):
ศาสตราจารย์ Andrew S. Tanenbaum ได้อธิบายเหตุผลที่โมเดล OSI พ่ายแพ้ต่อ TCP/IP ในเชิงพาณิชย์ผ่านทฤษฎี "การเผชิญหน้าของช้างสองตัว":

ช้างตัวแรกคือ ช่วงเวลาแห่งการวิจัยและพัฒนา (Standards Elephant) และช้างตัวที่สองคือ ช่วงเวลาแห่งการลงทุนติดตั้งใช้งานจริง (Implementation Elephant) มาตรฐาน OSI ถูกประกาศช้าเกินไป เมื่อมาตรฐานเสร็จสมบูรณ์ องค์กรต่างๆ ทั่วโลกได้ลงทุนติดตั้งระบบ TCP/IP ไปหมดแล้ว และเมื่อซอฟต์แวร์ OSI ถูกสร้างออกมาจริง กลับมีขนาดเทอะทะ ซับซ้อน และทำงานเชื่องช้า

"We reject: kings, presidents, and voting. We believe in: rough consensus and running code."
- David Clark, ผู้นำสถาปัตยกรรมอินเทอร์เน็ต (IETF, 1992)

แม้ว่า OSI จะล้มเหลวในตลาดพาณิชย์ แต่อุดมคติของโมเดล OSI กลับชนะอย่างเด็ดขาดในฐานะ แม่แบบการสอนและการจัดระเบียบความคิดทางวิศวกรรม (Pedagogical Reference Model) ที่ดีที่สุดในโลกจนถึงปัจจุบัน

2. Technical Glossary & Phonetics

อภิธานศัพท์เทคนิค สัทศาสตร์ และการประยุกต์ใช้ในระบบจริง (Nomenclature & Phonetics)

คำศัพท์เทคนิคมาตรฐานสากลตามข้อกำหนด IEEE/ISO และ RFC ที่นิสิตวิศวกรรมคอมพิวเตอร์ต้องออกเสียงและเข้าใจกลไกการทำงานระดับลึก:

Protocol Data Unit (PDU) โปร-โต-คอล ดา-ต้า ยู-นิต
หน่วยของข้อมูลที่ถูกส่งผ่านระหว่างเอนทิตีในเลเยอร์เดียวกันบนคนละโฮสต์ (Peer-to-Peer Process) ประกอบด้วยส่วนควบคุม (Header/Trailer) และส่วนข้อมูล (Payload) โดยในแต่ละเลเยอร์จะมีชื่อเรียกจำเพาะ: L7 เรียก Message, L4 เรียก Segment (TCP) หรือ Datagram (UDP), L3 เรียก Packet หรือ Datagram, L2 เรียก Frame, และ L1 เรียก Bit Stream
Context: ในเคอร์เนล Linux โครงสร้าง struct sk_buff จะเก็บพอยน์เตอร์ชี้ไปยังจุดเริ่มต้นของ PDU แต่ละระดับเพื่อส่งผ่านระหว่างไดรเวอร์การ์ดแลนและโปรโตคอลสแตก
Encapsulation & Decapsulation เอน-แคป-ซู-เล-ชัน และ ดี-แคป-ซู-เล-ชัน
Encapsulation: กระบวนการที่เลเยอร์ด้านบนส่งมอบ PDU ของตนให้แก่เลเยอร์ด้านล่าง โดยเลเยอร์ด้านล่างจะมองข้อมูลนั้นเป็นเพียงเพย์โหลดดิบ (Opaque Data) แล้วนำมาห่อหุ้มด้วยเฮดเดอร์ของตนเอง
Decapsulation: กระบวนการย้อนกลับที่ฝั่งผู้รับ เมื่อเลเยอร์ด้านล่างตรวจสอบความถูกต้องของเฮดเดอร์ตนเองแล้ว จะทำการแกะ (Strip) เฮดเดอร์ทิ้ง แล้วส่งต่อเฉพาะเพย์โหลดขึ้นไปยังเลเยอร์ด้านบน
Context: เคอร์เนลระบบปฏิบัติการใช้ฟังก์ชัน skb_push() เพื่อเลื่อนพอยน์เตอร์ถอยหลังในการเติม Header (Encapsulation) และใช้ skb_pull() เพื่อเลื่อนพอยน์เตอร์ไปข้างหน้าในการปลด Header (Decapsulation) โดยไม่ต้องคัดลอกหน่วยความจำ (Zero-Copy Architecture)
Physical Address (MAC Address / Link Address) ฟิ-ซิ-คัล แอด-เดรส / แมค แอด-เดรส
ที่อยู่ทางกายภาพระดับฮาร์ดแวร์ ขนาด 48 บิต (6 ไบต์ ตามมาตรฐาน IEEE 802 EUI-48) ถูกบันทึกลงในหน่วยความจำถาวร (EEPROM/OTP ROM) ของการ์ดแลน (NIC) แบ่งเป็น 24 บิตแรกคือรหัสผู้ผลิต (OUI: Organizationally Unique Identifier) และ 24 บิตหลังคือหมายเลขการ์ด ทำหน้าที่ระบุตัวตนบนสายสัญญาณเดียวกันสำหรับ Hop-to-Hop Delivery
Context: ตรวจสอบบนระบบปฏิบัติการจริงด้วยคำสั่ง 'ip link show' หรือ 'ethtool -P eth0' การ์ดแลนจะรับเฉพาะเฟรมที่มี Destination MAC ตรงกับตนเอง หรือเป็น Broadcast (FF:FF:FF:FF:FF:FF)
Logical Address (IP Address) ลอ-จิ-คัล แอด-เดรส / ไอ-พี แอด-เดรส
ที่อยู่เชิงตรรกะระดับโครงข่าย เช่น IPv4 ขนาด 32 บิต (4 ไบต์) หรือ IPv6 ขนาด 128 บิต (16 ไบต์) มีโครงสร้างแบบลำดับชั้น (Hierarchical Addressing) ประกอบด้วย Network ID และ Host ID ทำหน้าที่ระบุตำแหน่งโฮสต์ต้นทางและปลายทางข้ามระบบเครือข่ายอินเทอร์เน็ตสากล (Source-to-Destination / End-to-End Delivery) โดยแอดเดรสนี้จะไม่เปลี่ยนแปลงตลอดการเดินทางผ่านเราเตอร์
Context: ถูกเก็บในฟิลด์ saddr และ daddr ภายใน struct iphdr ในเคอร์เนล โดยเราเตอร์จะนำ Destination IP ไปค้นหาตารางเส้นทาง Forwarding Information Base (FIB)
Port Address พอร์ต แอด-เดรส
หมายเลขระบุโพรเซสหรือบริการเฉพาะภายในเครื่องโฮสต์ ขนาด 16 บิต (มีค่าตั้งแต่ 0 ถึง 65535) ใน Transport Layer แบ่งเป็น 3 กลุ่ม: Well-known Ports (0 ถึง 1023 เช่น HTTP: 80, HTTPS: 443, DNS: 53), Registered Ports (1024 ถึง 49151), และ Dynamic / Private / Ephemeral Ports (49152 ถึง 65535) ทำหน้าที่เป็นจุดส่งต่อข้อมูลระหว่างโปรโตคอลเครือข่ายและแอปพลิเคชัน (Process-to-Process Delivery)
Context: ตรวจสอบพอร์ตที่กำลังเปิดรอรับการเชื่อมต่อในเครื่องด้วยคำสั่ง 'ss -tulwn' หรือ 'netstat -tuln'
Ephemeral Port อิ-เฟม-เออ-รัล พอร์ต
หมายเลขพอร์ตชั่วคราวอายุสั้นที่เคอร์เนลของระบบปฏิบัติการจัดสรรให้กับโปรแกรมฝั่งไคลเอนต์ขณะเปิดการเชื่อมต่อออกไปภายนอก เมื่อโปรแกรมเสร็จสิ้นภารกิจและปิดการเชื่อมต่อ พอร์ตนี้จะถูกหน่วงเวลาไว้ชั่วครู่ (TIME_WAIT state) ก่อนส่งคืนกลับเข้าสู่พูลพอร์ตว่าง
Context: ในเคอร์เนล Linux ช่วงของ Ephemeral Port ถูกกำหนดไว้ในไฟล์ /proc/sys/net/ipv4/ip_local_port_range (โดยทั่วไปมีค่าเริ่มต้น 32768 ถึง 60999)
Socket 4-Tuple & 5-Tuple ซ็อก-เก็ต โฟร์-ทัป-เพิล
ชุดค่าผสมที่ไม่ซ้ำกันซึ่งระบบปฏิบัติการและอุปกรณ์ไฟร์วอลล์ใช้ระบุการเชื่อมต่อหนึ่งๆ อย่างสมบูรณ์: 4-Tuple ประกอบด้วย {Source IP, Source Port, Destination IP, Destination Port} และเมื่อรวมกับ Protocol (TCP หรือ UDP) จะกลายเป็น 5-Tuple ช่วยให้คอมพิวเตอร์สามารถเปิดหน้าเว็บเดียวกันหลายแท็บพร้อมกันได้โดยข้อมูลไม่ปะปนกัน
Context: เคอร์เนลใช้แฮชเทเบิล (Established Socket Hash Table) โดยนำ 4-Tuple มาผ่านฟังก์ชันแฮชเพื่อค้นหาโครงสร้าง struct sock ได้ในความซับซ้อน O(1)
Maximum Transmission Unit (MTU) แมก-ซิ-มัม ทรานส์-มิช-ชัน ยู-นิต
ขนาดเพย์โหลดสูงสุดของข้อมูลในระดับ Data Link Layer ที่สามารถส่งผ่านสายสัญญาณได้ในหนึ่งเฟรมโดยไม่ต้องตัดแบ่ง สำหรับมาตรฐาน Ethernet มาตรฐานมีค่าเท่ากับ 1,500 ไบต์ หาก IP Packet มีขนาดใหญ่กว่า MTU ของลิงก์ถัดไป เราเตอร์จะต้องทำกระบวนการ IP Fragmentation แยกเป็นแพ็กเก็ตย่อย
Context: ในเครือข่ายเซนเซอร์ไร้สาย (IEEE 802.15.4) มีขนาด MTU เพียง 127 ไบต์ จึงจำเป็นต้องมีเลเยอร์พิเศษ 6LoWPAN เพื่อทำ Header Compression และ Fragmentation
Service Data Unit (SDU) เซอร์-วิส ดา-ต้า ยู-นิต
หน่วยข้อมูลที่ถูกส่งผ่านข้ามอินเทอร์เฟซในแนวตั้งจากเลเยอร์ด้านบน (Layer N+1) ลงมายังเลเยอร์ด้านล่าง (Layer N) โดยเลเยอร์ N จะมองข้อมูลนี้เป็นเพย์โหลดดิบที่ต้องให้บริการส่งผ่าน จากนั้นจะนำ SDU มาเติมข้อมูลควบคุม Protocol Control Information (PCI หรือ Header) กลายเป็น PDU ของตนเองตามสมการ: PDU(N) = PCI(N) + SDU(N) และเมื่อส่งต่อขึ้นข้างบนจะมีความสัมพันธ์แบบสมมาตรคือ SDU(N) = PDU(N+1)
Context: ในระบบเครือข่ายคอมพิวเตอร์ ข้อมูล HTTP Message คือ SDU ของ Transport Layer เมื่อเติม TCP Header จะกลายเป็น TCP Segment (PDU ของ L4) และ TCP Segment นี้เองจะทำหน้าที่เป็น SDU ให้กับ Network Layer (L3) ต่อไป
Service Access Point (SAP) เซอร์-วิส แอ็ก-เซส พอยต์
จุดต่อประสานเชิงตรรกะในแนวตั้ง (Vertical Logical Interface) ตามมาตรฐาน ISO 7498 ที่เลเยอร์ด้านล่าง (Layer N) เปิดไว้เพื่อให้เลเยอร์ด้านบน (Layer N+1) เรียกใช้บริการเครือข่าย ทำหน้าที่เป็นตัวจำแนกมัลติเพล็กซ์ว่าเมื่อปลดเฮดเดอร์แล้ว ข้อมูลควรถูกส่งต่อขึ้นไปยังโปรโตคอลใดในชั้นถัดไป
Context: ใน Data Link Layer มีฟิลด์ EtherType (เช่น 0x0800 สำหรับ IPv4, 0x86DD สำหรับ IPv6), ใน Network Layer มีฟิลด์ Protocol (เช่น 6 สำหรับ TCP, 17 สำหรับ UDP), และใน Transport Layer มี Port Number ซึ่งทำหน้าที่เป็น SAP ส่งข้อมูลเข้าสู่ Application Process
Byte Overhead & Energy Drain ไบต์ โอเวอร์เฮด และ เอนเนอร์จี เดรน
สัดส่วนของบิตข้อมูลส่วนหัวและส่วนท้าย (Header + Trailer) ที่ระบบต้องส่งผ่านตัวกลางเพื่อควบคุมการสื่อสาร เทียบกับบิตข้อมูลเนื้อหาจริงของผู้ใช้ (User Payload) ในระบบที่มีสายขนาดใหญ่ผลกระทบคือการลดทอน Throughput แต่ในระบบเครือข่ายเซนเซอร์ไร้สาย (WSN) โอเวอร์เฮดทุกไบต์หมายถึงการผลาญพลังงานแบตเตอรี่ของโหนดโดยตรง
Context: การส่งข้อมูลคลื่นวิทยุในชิปเซนเซอร์ CC2420 (ไฟเลี้ยง V = 3.0V, กระแสส่ง I_tx = 17.4 mA, บิตเรต 250 kbps) เวลาส่ง 1 ไบต์ (8 บิต) คือ t = 8 / 250,000 = 32 μs พลังงานที่เผาผลาญไปคือ E = V × I × t = 3.0V × 17.4 mA × 32 μs = 1.6704 ไมโครจูล (μJ) ต่อไบต์! เฮดเดอร์ TCP/IP ดั้งเดิม 40 ไบต์จึงกินพลังงานไปถึง 66.8 μJ ต่อแพ็กเก็ต หากส่ง 100,000 ครั้ง จะผลาญพลังงานไป 6.68 จูล ซึ่งเทียบเท่าพลังงานที่ไมโครคอนโทรลเลอร์ใช้เลี้ยงตัวเองในโหมด Deep Sleep ได้นานถึง 4.4 เดือนเต็ม
3. Exhaustive Theoretical Rigor

สถาปัตยกรรมโมเดลอ้างอิง OSI 7 เลเยอร์ (The OSI 7-Layer Reference Model)

โมเดลการเชื่อมต่อระบบเปิด (Open Systems Interconnection: OSI) ตามมาตรฐาน ISO 7498 กำหนดกรอบแนวคิดแบบ 7 ลำดับชั้น แต่ละชั้นทำหน้าที่จำเพาะและให้บริการแก่ชั้นที่อยู่เหนือกว่า:

เลเยอร์ ชื่อและ PDU หน้าที่หลักทางวิศวกรรม (Core Responsibilities) โพรโทคอลและมาตรฐาน
Layer 7 Application Layer
PDU: Message		 ทำหน้าที่เป็นจุดต่อประสานระหว่างโปรแกรมประยุกต์ของผู้ใช้กับบริการเครือข่าย จัดการเรื่อง Network Virtual Terminal, การสืบค้นระเบียนชื่อ, บริการโอนย้ายไฟล์ และการแลกเปลี่ยนข้อความระดับสูง HTTP, HTTPS, DNS, SMTP, SSH, MQTT, CoAP (IoT)
Layer 6 Presentation Layer
PDU: Formatted Data		 รับผิดชอบด้านวากยสัมพันธ์ (Syntax) และความหมาย (Semantics) ของข้อมูล ได้แก่:
  • Translation: แปลงรหัสอักขระข้ามแพลตฟอร์ม (เช่น EBCDIC สู่ ASCII / UTF-8)
  • Encryption: เข้ารหัสและถอดรหัสความปลอดภัย (Cryptography เช่น TLS/AES)
  • Compression: บีบอัดข้อมูลเพื่อลดจำนวนบิตที่ต้องส่งผ่านสาย (Deflate, JPEG)
 TLS/SSL, ASN.1, MIME, JSON, Protobuf
Layer 5 Session Layer
PDU: Dialog Data		 ควบคุมการสนทนาและการแลกเปลี่ยนข้อมูล (Dialog Controller) กำหนดทิศทาง (Half-Duplex หรือ Full-Duplex) และระบบจุดตรวจสอบความสอดคล้อง (Checkpoint Synchronization) หากสายสื่อสารขาดตอน สามารถกู้คืนและส่งต่อเฉพาะข้อมูลหลังเช็กพอยต์ล่าสุดโดยไม่ต้องเริ่มส่งใหม่ตั้งแต่ต้น RPC, NetBIOS, SIP, Sockets API Session Mgmt
Layer 4 Transport Layer
PDU: Segment / Datagram		 รับผิดชอบการส่งข้อมูลระหว่างโพรเซสสู่โพรเซส (Process-to-Process Delivery):
  • Port Addressing: กำกับหมายเลขพอร์ตเพื่อส่งเข้าสู่แอปพลิเคชันที่ถูกต้อง
  • Segmentation & Reassembly: หั่นข้อมูลขนาดใหญ่เป็นชิ้นย่อยและเรียงลำดับ
  • Connection Control: มีทั้งแบบมีสายสัมพันธ์ (TCP) และไร้สายสัมพันธ์ (UDP)
  • Flow & Error Control: ควบคุมอัตราการส่งไม่ให้ท่วมเครื่องรับและตรวจซ้ำ (ACK)
 TCP (RFC 793), UDP (RFC 768), SCTP, QUIC
Layer 3 Network Layer
PDU: Packet / Datagram		 รับผิดชอบการนำพาแพ็กเก็ตจากโฮสต์ต้นทางไปยังโฮสต์ปลายทางข้ามระบบเครือข่ายหลายเครือข่าย (Source-to-Destination / End-to-End Delivery):
  • Logical Addressing: กำหนดหมายเลขประจำเครื่องทั่วโลก (IPv4 / IPv6)
  • Routing: หาเส้นทางที่สั้นและมีประสิทธิภาพที่สุดผ่านเราเตอร์ (OSPF, BGP)
  • Packet Forwarding & Fragmentation: ส่งต่อแพ็กเก็ตและตัดแบ่งตาม MTU
 IPv4 (RFC 791), IPv6 (RFC 8200), ICMP, OSPF, BGP, RPL
Layer 2 Data Link Layer
PDU: Frame		 รับผิดชอบการส่งผ่านเฟรมข้อมูลระหว่างสองโหนดที่เชื่อมต่ออยู่บนสายสัญญาณเดียวกันโดยตรง (Hop-to-Hop / Node-to-Node Delivery):
  • Framing: กำหนดจุดเริ่มต้นและจุดสิ้นสุดของข้อมูลด้วยบิตแฟล็กพิเศษ
  • Physical Addressing: กำกับที่อยู่ MAC ของการ์ดแลนในแต่ละฮอป
  • Flow & Error Control: ตรวจสอบข้อผิดพลาดระดับสายสัญญาณด้วย CRC/FCS
  • Media Access Control (MAC): ควบคุมการแย่งใช้ช่องสัญญาณรวม (CSMA/CD, CSMA/CA)
 IEEE 802.3 (Ethernet), IEEE 802.11 (Wi-Fi), PPP, IEEE 802.15.4 MAC
Layer 1 Physical Layer
PDU: Bit Stream		 รับผิดชอบการแปลงบิตดิจิทัล 0 และ 1 เป็นสัญญาณกายภาพ (แรงดันไฟฟ้า คลื่นแสง หรือคลื่นวิทยุ) วิ่งผ่านตัวกลาง:
  • Signal Representation: การแปลงรหัสสัญญาณทางไฟฟ้า (Line Coding เช่น NRZ, Manchester)
  • Data Rate: กำหนดอัตราการส่งบิตต่อวินาที (Bit Rate / Duration)
  • Bit Synchronization: ซิงโครไนซ์สัญญาณนาฬิการะหว่างตัวส่งและตัวรับ
  • Interface Characteristics: กำหนดพิน รูปร่างหัวต่อ และระดับแรงดันไฟฟ้า
 100BASE-TX, 1000BASE-T, Fiber Optics, 2.4 GHz RF (CC2420 PHY)

สถาปัตยกรรมชุดโพรโทคอล TCP/IP (The 5-Layer Internet Architecture)

ในทางวิศวกรรมเชิงปฏิบัติ ระบบเครือข่ายอินเทอร์เน็ตสากลไม่ได้นำโครงสร้าง 7 ชั้นของ OSI มาใช้งานจริง แต่เลือกใช้ ชุดโพรโทคอล TCP/IP (TCP/IP Protocol Suite) ซึ่งมีโครงสร้าง 5 ลำดับชั้นตามหลักการปฏิบัติการ:

1. การยุบรวมชั้นบน (Layers 5, 6, 7 ยุบเป็นหนึ่ง)

ในสถาปัตยกรรม TCP/IP หน้าที่ของ Application, Presentation, และ Session ถูกหลอมรวมอยู่ภายใน Application Layer เพียงชั้นเดียว สถาปัตยกรรมเชื่อมั่นในปรัชญา "End-to-End Principle" ว่าการเข้ารหัสข้อมูล (TLS) หรือการแปลโครงสร้างข้อมูล (JSON/Protobuf) ควรเป็นภาระหน้าที่ของแอปพลิเคชันส่วนปลายของผู้ใช้ ไม่ควรให้แกนกลางเครือข่ายมาแทรกแซง

2. สถาปัตยกรรมนาฬิกาทราย (The Hourglass Model)

TCP/IP มีรูปร่างแคบตรงกลางอย่างโดดเด่น: ใน Network Layer มีโพรโทคอล IP (Internet Protocol) เป็นแกนร่วมหนึ่งเดียว (The Narrow Waist) ที่เชื่อมโลกทั้งใบเข้าด้วยกัน โดยด้านล่างสามารถเชื่อมต่อกับเทคโนโลยี Physical/Data Link นับร้อยชนิด (Ethernet, Wi-Fi, 5G, Fiber, 802.15.4) และด้านบนสามารถรองรับแอปพลิเคชันนับล้านชนิดได้อย่างไร้รอยต่อ

กระบวนการเดินทางของข้อมูล: Encapsulation & Decapsulation

เมื่อผู้ใช้พิมพ์ข้อความหรือกดส่งคำขอในเว็บเบราว์เซอร์ ข้อมูลจะถูกแปลงและห่อหุ้มตามลำดับขั้น:

  1. Layer 5 (Application): สร้างข้อความข้อมูลดิบ (User Message) เช่น ข้อความคำขอ GET /index.html HTTP/1.1
  2. Layer 4 (Transport): นำ Message มาห่อหุ้มด้วย TCP Header ขนาดขั้นต่ำ 20 ไบต์ (ระบุ Source Port, Destination Port, Sequence Number, Control Flags) กลายเป็น TCP Segment
  3. Layer 3 (Network): นำ TCP Segment มาห่อหุ้มด้วย IP Header ขนาดขั้นต่ำ 20 ไบต์ (ระบุ Source IP, Destination IP, Time to Live: TTL, Protocol Number: 0x06 สำหรับ TCP) กลายเป็น IP Packet / Datagram
  4. Layer 2 (Data Link): นำ IP Packet มาห่อหุ้มด้วย Ethernet Header ขนาด 14 ไบต์ (ระบุ Source MAC, Destination MAC, EtherType: 0x0800 สำหรับ IPv4) ที่ด้านหน้า และเติม Frame Check Sequence (FCS/CRC32) ขนาด 4 ไบต์ ที่ด้านท้าย กลายเป็น Ethernet Frame (ขนาดโอเวอร์เฮดรวมของ L2 คือ 18 ไบต์)
  5. Layer 1 (Physical): เติมสัญญาณนำร่อง Preamble (7 ไบต์) + Start Frame Delimiter (1 ไบต์) และเว้นช่องว่างระหว่างเฟรม Inter-Packet Gap (12 ไบต์) แล้วแปลงบิตทั้งหมดเป็นสัญญาณคลื่นแม่เหล็กไฟฟ้าหรือพัลส์แสงยิงออกสู่ตัวกลางจริง

  • การส่งข้อมูลเซนเซอร์ตรวจวัด (IoT Telemetry): เซนเซอร์ส่งข้อมูลอุณหภูมิและความชื้นขนาด Payload = 64 ไบต์

  • L3 IPv4 Header: 20 ไบต์ (เมื่อไม่มีออปชันเสริม)

ตัวอย่างที่ 2.3: การติดตามการกลายพันธุ์ของแอดเดรสทีละฮอป (Hop-by-Hop MAC Mutation Tracing)
สถานการณ์ทางวิศวกรรม:
เครื่องไคลเอนต์ Host A ต้องการส่งข้อมูลไปยังเครื่องเซิร์ฟเวอร์ Host B ข้ามเครือข่ายอินเทอร์เน็ตผ่านเราเตอร์สองตัว (Router R1 และ Router R2) โดยมีแผนผังและแอดเดรสดังนี้:
  • Host A: IP = 192.168.1.10, MAC = AA:AA:AA:AA:AA:AA
  • Router R1 (Interface 1 ชี้หา Host A): IP = 192.168.1.1, MAC = 11:11:11:11:11:11
  • Router R1 (Interface 2 ชี้หา R2): IP = 10.0.0.1, MAC = 12:12:12:12:12:12
  • Router R2 (Interface 1 ชี้หา R1): IP = 10.0.0.2, MAC = 21:21:21:21:21:21
  • Router R2 (Interface 2 ชี้หา Host B): IP = 172.16.0.1, MAC = 22:22:22:22:22:22
  • Host B: IP = 172.16.0.50, MAC = BB:BB:BB:BB:BB:BB
จงแสดงตารางฟิลด์แอดเดรส {Source IP, Destination IP, Source MAC, Destination MAC} ภายในเฟรมข้อมูล ณ จุดสังเกตในแต่ละช่วงฮอป
ตารางวิเคราะห์การเปลี่ยนแปลงแอดเดรสในแต่ละช่วงการเดินทาง:
ช่วงการเดินทาง (Hop) Source IP (L3) Destination IP (L3) Source MAC (L2) Destination MAC (L2)
Hop 1: Host A → R1 192.168.1.10 172.16.0.50 AA:AA:AA:AA:AA:AA 11:11:11:11:11:11
Hop 2: R1 → R2 192.168.1.10 172.16.0.50 12:12:12:12:12:12 21:21:21:21:21:21
Hop 3: R2 → Host B 192.168.1.10 172.16.0.50 22:22:22:22:22:22 BB:BB:BB:BB:BB:BB
ข้อสรุปเชิงสถาปัตยกรรม (Architectural Invariant):
  1. Logical IP Address เป็นค่าคงที่ระดับ End-to-End: Source IP และ Destination IP จะไม่มีการเปลี่ยนแปลงเลยตลอดการเดินทางจาก Host A ถึง Host B (ยกเว้นกรณีมีการทำ NAT)
  2. Physical MAC Address มีการกลายพันธุ์ระดับ Hop-to-Hop: ในแต่ละครั้งที่แพ็กเก็ตผ่านเราเตอร์ เราเตอร์จะแกะเฟรม L2 เดิมทิ้ง และสร้างเฟรม L2 ใหม่ขึ้นมาห่อหุ้ม โดยใส่ Source MAC ของอินเทอร์เฟซขาออกของตน และใส่ Destination MAC ของอุปกรณ์ถัดไปที่สืบค้นได้จากตาราง ARP Cache
ตัวอย่างที่ 2.4: การแยกแยะการเชื่อมต่อพร้อมกันด้วย Socket 4-Tuple (Connection Demultiplexing)
สถานการณ์ทางวิศวกรรม:
ผู้ใช้เปิดคอมพิวเตอร์ไคลเอนต์ (IP = 192.168.1.100) แล้วเปิดเว็บเบราว์เซอร์ใช้งาน 3 งานพร้อมกัน:
  • แท็บที่ 1: เข้าชมเว็บเซิร์ฟเวอร์ A (IP = 203.0.113.10, พอร์ต 443 HTTPS)
  • แท็บที่ 2: เข้าชมเว็บเซิร์ฟเวอร์ A เดียวกัน (IP = 203.0.113.10, พอร์ต 443 HTTPS) เพื่อดาวน์โหลดไฟล์ขนาดใหญ่
  • แท็บที่ 3: เบราว์เซอร์สืบค้นชื่อโดเมนจาก DNS Server (IP = 8.8.8.8, พอร์ต 53 UDP)
จงแสดงโครงสร้าง 4-Tuple ที่เคอร์เนลของระบบปฏิบัติการสร้างขึ้น และอธิบายว่าเมื่อแพ็กเก็ตข้อมูลตอบกลับวิ่งเข้ามาถึงการ์ดแลน เคอร์เนลอาศัยกลไกใดในการส่งข้อมูลเข้าสู่แท็บเบราว์เซอร์ที่ถูกต้องได้อย่างแม่นยำ 100%
ตารางแจกแจงโครงสร้าง 4-Tuple ใน Socket Table ของระบบปฏิบัติการ:
เซสชัน / งาน Source IP Source Port (Ephemeral) Destination IP Destination Port Protocol
แท็บ 1 (เว็บ A) 192.168.1.100 51234 203.0.113.10 443 TCP
แท็บ 2 (เว็บ A ดาวน์โหลด) 192.168.1.100 51235 203.0.113.10 443 TCP
แท็บ 3 (DNS Lookup) 192.168.1.100 58921 8.8.8.8 53 UDP
กลไกการแยกแยะข้อมูลในเคอร์เนล (Demultiplexing Mechanism):
แม้ว่าแท็บที่ 1 และแท็บที่ 2 จะเชื่อมต่อไปยังเซิร์ฟเวอร์เครื่องเดียวกัน (Destination IP = 203.0.113.10) และพอร์ตปลายทางเดียวกัน (Destination Port = 443) แต่เคอร์เนลฝั่งไคลเอนต์ได้จัดสรร Ephemeral Port คนละหมายเลข (51234 และ 51235) ให้แก่สองโพรเซส
เมื่อเซิร์ฟเวอร์ส่งข้อมูลกลับมา แพ็กเก็ตตอบกลับจะมี Destination Port เท่ากับ 51234 หรือ 51235 เคอร์เนลจะนำค่า 4-Tuple ไปผ่านฟังก์ชันแฮชเพื่อดึงพอยน์เตอร์โครงสร้าง struct sock ที่ตรงกัน และส่งข้อมูลเข้าสู่คิวรับบัฟเฟอร์ (Receive Buffer) ของโปรเซสแท็บนั้นโดยไม่มีการชนกันอย่างเด็ดขาด
4. Hardware & Silicon Reality Check

กายวิภาคการ์ดแลน ชิปเซตควบคุม และหน่วยความจำ DMA (Silicon & Hardware Reality)

ในเชิงวิศวกรรมฮาร์ดแวร์ เลเยอร์ทั้ง 7 ไม่ได้เป็นเพียงบล็อกไดอะแกรมบนกระดาษ แต่ถูกแบ่งแยกการทำงานจริงระหว่าง ชิปเซตฮาร์ดแวร์ (Silicon ASIC) และ ซอฟต์แวร์เคอร์เนล (OS Kernel Space):

โครงสร้างสถาปัตยกรรมภายในของการ์ดแลน (NIC Architecture)

  • ชิปเซต Physical Transceiver (PHY Chip): รับผิดชอบ Layer 1 แปลงสัญญาณแอนะล็อกระดับแรงดันไฟฟ้าจากขั้วต่อ RJ-45 หรือพัลส์แสงจากโมดูล SFP+ ให้กลายเป็นบิตดิจิทัลขนาน ส่งต่อไปยังชิป MAC ผ่านอินเทอร์เฟซบัส MII (Media Independent Interface) หรือ RGMII (Reduced Gigabit MII)
  • ชิป MAC Controller ASIC: รับผิดชอบ Layer 2 ทำหน้าที่ประมวลผลการคำนวณ CRC32 แบบเรียลไทม์ผ่านวงจรกะรีจิสเตอร์เชิงเส้น (LFSR), ตรวจสอบ Destination MAC ว่าตรงกับฮาร์ดแวร์หรือไม่, และตัดเฟรมส่วนหัวและส่วนท้ายออก
  • DMA Ring Buffers (หน่วยความจำส่งต่อตรง O(1)): การ์ดแลนความเร็วสูงไม่รบกวนซีพียูในการคัดลอกข้อมูลทีละไบต์ แต่ใช้สถาปัตยกรรม Bus Master DMA (Direct Memory Access) โดยมีตัวชี้คิวแบบวงแหวน (RX Ring Buffer และ TX Ring Buffer) ในแรมของระบบ เมื่อเฟรมเดินทางมาถึง การ์ดแลนจะยิงข้อมูลลงแรมโดยตรงผ่านบัส PCIe แล้วส่งสัญญาณขัดจังหวะ MSI-X Interrupt ปลุกซีพียูให้มารับแพ็กเก็ตไปประมวลผลต่อ
  • Hardware Offloading Engines: เพื่อให้บรรลุความเร็วระดับสายสัญญาณ (Wire Speed 10 Gbps ถึง 100 Gbps) โดยไม่ทำให้ซีพียูรับภาระหนัก ชิปการ์ดแลนสมัยใหม่มีวงจรคำนวณ Checksum ภายในฮาร์ดแวร์ (Checksum Offload) และวงจรช่วยหั่นท่อนข้อมูล TCP ขนาดยักษ์ 64 KB ให้เป็นขนาด MTU 1,500 ไบต์โดยอัตโนมัติ (TCP Segmentation Offload: TSO)

ทดสอบความเข้าใจแก่นแท้ทางวิศวกรรมของบทเรียนนี้ด้วยตนเอง คลิกปุ่มเพื่อตรวจคำตอบและเหตุผลเชิงลึก:

ข้อที่ 1: เหตุใดเราเตอร์จึงสามารถนำพาแพ็กเก็ตข้ามเครือข่ายได้ โดยอาศัยเพียง 3 เลเยอร์ล่าง (Physical, Data Link, Network) โดยไม่ต้องเปิดดูเลเยอร์ Transport หรือ Application?
เหตุผลเชิงวิศวกรรม: ภารกิจหลักของเราเตอร์คือการหาเส้นทางและการส่งต่อแพ็กเก็ต (Path Determination & Packet Forwarding) ข้ามเครือข่าย ซึ่งใช้ข้อมูลเพียง Logical Destination IP Address ที่ระบุอยู่ในส่วนหัวของ Network Layer (Layer 3) เมื่อเราเตอร์ตรวจสอบ IP ปลายทางและเปิดตารางเส้นทาง FIB ทราบอินเทอร์เฟซขาออกแล้ว เราเตอร์จะทำการห่อหุ้มเฟรม Data Link (Layer 2) ใหม่ แล้วส่งออกทางฮาร์ดแวร์ Physical (Layer 1) ทันที การไม่แตะต้องหรือเปิดดูเนื้อหาใน Layer 4 ถึง 7 เป็นไปตามหลักการ Information Hiding และ End-to-End Principle ซึ่งช่วยลดความล่าช้าในการประมวลผล (Processing Latency) ของเราเตอร์ให้เหลือน้อยที่สุด
ข้อที่ 2: หากเครื่องคอมพิวเตอร์ A ส่งข้อมูลไปยังเครื่องคอมพิวเตอร์ B บนเครือข่ายแลนเดียวกันผ่านสวิตช์ L2 ข้อมูลจะเดินทางขึ้นไปถึงเลเยอร์ใดในตัวสวิตช์?
เหตุผลเชิงวิศวกรรม: สวิตช์แลนทั่วไปเป็นอุปกรณ์เลเยอร์ 2 (Data Link Layer Device) สวิตช์จะรับสัญญาณบิตจากสายเคเบิล (Layer 1) ประกอบเป็นเฟรมเพื่ออ่าน Destination MAC Address และตรวจสอบรหัสข้อผิดพลาด CRC32 ใน Layer 2 เพื่อตัดสินใจสลับพอร์ตส่งต่อตามตาราง MAC Address Table จากนั้นจะส่งเฟรมออกทางพอร์ตปลายทางโดย ไม่มีการถอดหรืออ่าน Layer 3 (IP) เลย ดังนั้นข้อมูลจึงเดินทางขึ้นไปสูงสุดเพียง Layer 2 ในตัวสวิตช์เท่านั้น
ข้อที่ 3: ในการคำนวณประสิทธิภาพ Throughput เหตุใด Bandwidth-Delay Product (BDP) จึงเป็นตัวกำหนดขนาดหน้าต่างรับข้อมูล (Receive Window Size) ของ TCP?
เหตุผลเชิงวิศวกรรม: BDP = Bandwidth × Round-Trip Time คือปริมาณข้อมูลสูงสุดที่สามารถเคลื่อนที่อยู่ในสายสัญญาณพร้อมๆ กัน หากขนาดของ TCP Window มีค่าน้อยกว่า BDP เครื่องส่งจะส่งข้อมูลจนเต็มหน้าต่างแล้วจำเป็นต้องหยุดนิ่งเพื่อรอสัญญาณตอบรับ ACK จากเครื่องรับ ทำให้สายสัญญาณความเร็วสูงกลายเป็นท่อว่างเปล่าที่ไม่ได้ใช้งาน การกำหนดให้ Window Size มีขนาดเท่ากับหรือมากกว่า BDP ทำให้เครื่องส่งสามารถฉีดข้อมูลลงท่อได้อย่างต่อเนื่อง 100% เต็มความจุของลิงก์
ข้อที่ 4: ความแตกต่างพื้นฐานระหว่าง Service Access Point (SAP) และ Protocol Data Unit (PDU) คืออะไร?
เหตุผลเชิงวิศวกรรม: SAP คือ จุดประสานงานในแนวตั้ง (Vertical Interface) ระหว่างเลเยอร์ที่อยู่ติดกันบนเครื่องเดียวกัน เช่น จุดที่เลเยอร์ N ให้บริการแก่เลเยอร์ N+1 ส่วน PDU คือ รูปแบบโครงสร้างข้อมูลในแนวนอน (Horizontal Protocol) ที่เลเยอร์ระดับเดียวกันบนคนละเครื่อง (Peer-to-Peer) ใช้สนทนาและสื่อสารระหว่างกันตามข้อกำหนดของโปรโตคอล
ข้อที่ 5: หากแอปพลิเคชันต้องการส่งข้อมูลแบบรวดเร็วที่สุดโดยไม่สนใจว่าแพ็กเก็ตจะตกหล่นหรือไม่ ควรเลือกใช้โปรโตคอลใดใน Transport Layer และเพราะเหตุใด?
เหตุผลเชิงวิศวกรรม: ควรเลือกใช้ UDP (User Datagram Protocol) เนื่องจากเป็นโปรโตคอลแบบไร้สายสัมพันธ์ (Connectionless) ไม่มีขั้นตอนการเริ่มจับมือ 3 จังหวะ (Three-way Handshake) ไม่มีกลไกการส่งซ้ำเมื่อแพ็กเก็ตสูญหาย และไม่มีการควบคุมความคับคั่งที่คอยหน่วงเวลา ทำให้มีค่าความล่าช้า (Latency) ต่ำที่สุด เหมาะสำหรับการสื่อสารแบบเรียลไทม์ เช่น วิดีโอสตรีมมิง การสนทนาด้วยเสียง และเซนเซอร์ IoT
ข้อที่ 6: เหตุใดในเครือข่ายเซนเซอร์ไร้สาย (WSN) สถาปัตยกรรม 7 เลเยอร์ของ OSI จึงสร้างปัญหาคอขวดด้านพลังงาน และวิศวกรแก้ปัญหาด้วยวิธีใด?
เหตุผลเชิงวิศวกรรม: สถาปัตยกรรม OSI เพิ่มขนาดโอเวอร์เฮดของเฮดเดอร์ในทุกๆ ชั้น ซึ่งในแพ็กเก็ตเซนเซอร์ที่มีเพย์โหลดขนาดเล็ก (เช่น 10-20 ไบต์) โอเวอร์เฮดนี้จะกินสัดส่วนพลังงานในการส่งคลื่นวิทยุไปมากกว่า 60-70% วิศวกร WSN จึงแก้ปัญหานี้โดยใช้ การออกแบบข้ามชั้นหน้าที่ (Cross-Layer Optimization) เช่น ให้เลเยอร์ Routing นำข้อมูลระดับพลังงานคงเหลือของแบตเตอรี่และความแรงของสัญญาณคลื่นวิทยุ (RSSI) จาก Physical Layer มาใช้ตัดสินใจเลือกเส้นทางโดยตรง โดยไม่ผ่านการแยกชั้นอย่างเคร่งครัด
7. Synthesis & Mental Model

สังเคราะห์โมเดลความคิด: เปรียบเทียบ OSI vs TCP/IP vs WSN Cross-Layer

ตารางสังเคราะห์เปรียบเทียบแก่นความคิดเพื่อสร้างแผนที่ความรู้ที่สมบูรณ์ในสมองของวิศวกร:

มิติการเปรียบเทียบ โมเดลอ้างอิง OSI (7 เลเยอร์) ชุดโพรโทคอล TCP/IP (5 เลเยอร์) เครือข่ายเซนเซอร์ WSN / IoT
1. ปรัชญาการออกแบบ ความสมบูรณ์แบบเชิงทฤษฎี แยกหน้าที่เด็ดขาด (Strict Layering) ความเรียบง่ายเชิงปฏิบัติ (Rough consensus and running code) ประหยัดพลังงานเป็นเอกเทศ (Energy-centric Optimization)
2. จำนวนชั้นและการจัดกลุ่ม 7 ชั้น (แยก Application, Presentation, Session อิสระ) 5 ชั้น (หลอมรวม 3 ชั้นบนเข้าเป็น Application Layer) 4-5 ชั้น ยุบรวมหรือใช้ Cross-Layer Optimization
3. การจัดการเฮดเดอร์ เติมเฮดเดอร์เต็มรูปแบบในทุกชั้น มีขนาดเทอะทะ เฮดเดอร์มาตรฐาน (IPv4: 20B, TCP: 20B) บีบอัดเฮดเดอร์ระดับสูง (6LoWPAN บีบเหลือ 2-4 ไบต์)
4. การแพร่หลายและสถานะ ล้มเหลวเชิงพาณิชย์ แต่ชนะเด็ดขาดในฐานะ โมเดลเพื่อการสอน มาตรฐานโดยพฤตินัย (De facto Standard) ของอินเทอร์เน็ตสากล มาตรฐานแกนหลักของโครงข่าย IoT ยุคใหม่ (IEEE 802.15.4 / ZigBee)
5. ขอบเขตการทำงานของสวิตช์/โหนด แยกบริบท End System และ Intermediate Relay ชัดเจน เราเตอร์ดูถึง Layer 3 สวิตช์ดูถึง Layer 2 เซนเซอร์โหนดทุกตัวอาจทำหน้าที่เป็นทั้ง Host และ Router (Ad-hoc Mesh)
