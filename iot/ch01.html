305141 Introduction to Internet of Things Part 1: Overview, Components, Architecture บทที่ 1 จาก 6

บทนำอินเทอร์เน็ตของสรรพสิ่ง: จากตู้เย็นอัจฉริยะสู่ระบบขับเคลื่อนด้วยเหตุการณ์

เข้าใจ IoT ไม่ใช่แค่การต่ออุปกรณ์ขึ้น Internet แต่คือระบบฝังตัวที่ออกแบบมาเพื่อแอปพลิเคชันเฉพาะ มีข้อจำกัดด้านพลังงาน แบนด์วิดท์ และต้องเคารพพลวัตของระบบทางกายภาพ
1. Historical Genesis

ที่มาทางประวัติศาสตร์: IoT ไม่ได้เกิดขึ้นในชั่วข้ามคืน

คำว่า Internet of Things กลายเป็นข่าวและกระแสนิยมทางการตลาดอย่างรวดเร็ว แต่เบื้องหลังคำโฆษณา IoT คือเทคโนโลยีที่หยั่งรากลึกจากสามสายงานวิจัยมาก่อนหน้านาน ได้แก่ Pervasive Information Systems, Sensor Networks, และ Embedded Computing

หลักสูตร 305141 ของ อ.ตั้ม ย้ำไว้ว่า คำที่อธิบายความจริงของเทคโนโลยีนี้ได้แม่นกว่าคือ IoT system ไม่ใช่ Internet of Things ลอยๆ เพราะอุปกรณ์ส่วนใหญ่ถูกเชื่อมเป็นระบบเฉพาะกิจ (purpose-specific systems) ไม่ใช่เครื่องมือเปิดกว้างบนเครือข่ายทั่วโลกเหมือนเบราว์เซอร์หรือพีซี

กับดักข้อสอบ: ถ้าตอบว่า IoT คือ "อุปกรณ์ทุกอย่างต่อเน็ต" ยังถือว่าเข้าใจไม่ถึงแก่น ระบบ IoT จริงต้องออกแบบเพื่อชุดแอปพลิเคชันหนึ่งหรือหลายแอปที่เกี่ยวข้องกัน และต้องคำนึงถึงพลวัตของระบบทางกายภาพเป็นหลัก
2. Technical Glossary

นิยามศัพท์และคำอ่านสัทศาสตร์ภาษาไทย

Internet of Things (IoT) อิน-เทอร์-เน็ต ออฟ ทิงส์
วัตถุทางกายภาพที่มีเซนเซอร์ ความสามารถประมวลผล ซอฟต์แวร์ และเทคโนโลยีสื่อสาร เพื่อแลกเปลี่ยนข้อมูลกับอุปกรณ์และระบบอื่นผ่านเครือข่าย
IoT System ไอ-โอ-ที ซิส-เทม
ระบบเฉพาะกิจที่รวมอุปกรณ์ เซนเซอร์ แอคชูเอเตอร์ ตัวประมวลผล และเครือข่าย เข้าด้วยกันเพื่อวัตถุประสงค์ที่กำหนดไว้ ไม่ใช่กลุ่มอุปกรณ์อินเทอร์เน็ตแบบไร้ทิศทาง
Sensor เซน-เซอร์
ตัวตรวจวัดสภาวะทางกายภาพ เช่น อุณหภูมิ ความเร่ง แสง แก๊ส แล้วแปลงเป็นสัญญาณให้ระบบประมวลผล
Actuator แอค-ชู-เอ-เตอร์
ตัวกระทำที่เปลี่ยนคำสั่งดิจิทัลเป็นผลทางกายภาพ เช่น มอเตอร์ วาล์ว รีเลย์ หลอดไฟ
MEMS เมมส์
Microelectromechanical Systems เซนเซอร์จิ๋วราคาถูกกินไฟต่ำ เช่น accelerometer, gyroscope, chemical sensor ซึ่งเป็นเชื้อเพลิงหลักของยุค IoT
Node / End-Device โนด / เอนด์-ดี-ไวซ์
โหนดปลายทางของเครือข่าย มีเซนเซอร์และ/หรือแอคชูเอเตอร์ ตัวประมวลผล หน่วยความจำ และ network interface
Hub ฮับ
จุดเชื่อมต่อระดับแรกระหว่างกลุ่มโหนดกับเครือข่ายที่เหลือ มักทำงานด้วย Internet Protocol
Fog / Edge Processing ฟอก / เอดจ์
การประมวลผลใกล้โหนด เพื่อลด latency และลดปริมาณข้อมูลที่ต้องส่งขึ้นคลาวด์
Event-Driven อี-เวนท์-ดรีฟ-เวิน
สถาปัตยกรรมที่อ่านค่าเมื่อเกิดเงื่อนไขหรือเหตุการณ์ แทนการสุ่มตัวอย่างเป็นคาบคงที่ตลอดเวลา
Aperiodic Sampling เอ-เพ-รี-โอ-ดิก แซม-ปลิง
การสุ่มตัวอย่างแบบไม่เป็นคาบ ช่วยประหยัดพลังงานและแบนด์วิดท์เมื่อเทียบกับ time-series คงที่
3. What is IoT

IoT คืออะไรกันแน่: นิยามที่ใช้ในชั้นเรียน

ยังไม่มีนิยามเดียวที่ทุกฝ่ายยอมรับ แต่ในสไลด์ อ.ตั้ม ระบุความเป็นไปได้ไว้ดังนี้:

  • อุปกรณ์ทางกายภาพที่เปิดใช้การสื่อสารผ่านเครือข่าย แม้หลายเครื่องจะไม่ได้รัน Internet Protocol โดยตรง
  • Sensor network แบบ soft real-time
  • เครือข่ายไดนามิกของอุปกรณ์ฝังตัวที่พัฒนาต่อเนื่อง

ลักษณะเด่น 2 ประการที่ต้องจำ

  1. Designed for one or a set of applications ไม่ใช่กลุ่มอุปกรณ์อินเทอร์เน็ตที่กระจัดกระจายไร้จุดหมาย
  2. Takes into account the dynamics of physical systems ต้องเคารพพฤติกรรมของโลกจริงที่เปลี่ยนแปลงตลอดเวลา

ระบบ IoT อาจมีเซนเซอร์เป็นหลัก หรือมีแอคชูเอเตอร์จำนวนมากในบางกรณี เป้าหมายร่วมคือประมวลผลสัญญาณและข้อมูลอนุกรมเวลา (time-series)

4. Technology Roots

รากเหง้าสามสาย: Sensor Networks, Embedded Computing, MEMS

Traditional Sensor Network vs IoT Sensor Research

Traditional Sensor Network

  • เก็บข้อมูลที่อัตราข้อมูลต่ำมาก
  • ส่งข้อมูลดิบไปยังเซิร์ฟเวอร์กลาง
  • ไม่เน้น in-network processing
  • โฟกัสที่การเก็บข้อมูลเป็นหลัก

IoT Sensor Research

  • โหนดมีทั้ง sense และ process
  • มีแอคชูเอเตอร์โต้ตอบกลับโลกจริง
  • เน้น edge/fog processing
  • ออกแบบเพื่อแอปพลิเคชันเฉพาะ

Embedded Computing

เดิมเน้นอุปกรณ์ standalone หรือเครือข่ายที่ผูกกันแน่น เช่น ระบบในยานพาหนะ ขอบเขตหลักคือ consumer electronics กับ cyber-physical systems ทั้งสองเน้นระบบวิศวกรรมที่มีเป้าหมายชัดเจน

MEMS Sensors

ความพร้อมของเซนเซอร์ MEMS ราคาถูกกินไฟต่ำ เช่น accelerometer, gyroscope, chemical sensor ทำให้แอปพลิเคชัน IoT ขยายออกนอกห้องทดลองและโรงงาน และดันระบบ IoT เข้าสู่งาน signal processing อย่างจริงจัง

5. System Anatomy

กายวิภาคของระบบ IoT: 4 องค์ประกอบหลัก

ถอดโครงสร้างโหนดและระบบจากสไลด์ Part 1 ได้เป็น 4 องค์ประกอบที่ขาดไม่ได้:

1. Sensing

เซนเซอร์อ่านค่าทางกายภาพ
แสง เสียง ความดัน อุณหภูมิ

2. Processing

ไมโครคอนโทรลเลอร์และหน่วยความจำ
กรองข้อมูล ตรวจเหตุการณ์

3. Actuating

แอคชูเอเตอร์เปลี่ยนคำสั่งเป็นผลจริง
มอเตอร์ วาล์ว รีเลย์

4. Networking

Network interface ส่งข้อมูลและรับคำสั่ง
มีทั้งแบบรัน IP และไม่รัน IP

องค์ประกอบในภาพรวมของระบบ

องค์ประกอบหน้าที่ข้อสังเกตสำคัญ
Physical plant / environment ระบบกายภาพที่ IoT โต้ตอบด้วย ใช้คำว่า plant และ environment สลับกันได้ในสไลด์
Nodes (leaves) โหนดปลายทาง รวม sensor/actuator, processor, memory, network interface บางโหนดรัน Internet Protocol บางโหนดไม่รัน
Hubs เชื่อมต่อระดับแรกระหว่างโหนดกับเครือข่ายที่เหลือ มักรัน IP
Fog processors ประมวลผลชุดโหนดและฮับในพื้นที่ ลด latency แต่มีพลังคำนวณน้อยกว่าคลาวด์
Cloud servers ประมวลผลและเก็บข้อมูลขนาดใหญ่ มาพร้อมปัญหา system management
6. Three-Tier Architecture

สถาปัตยกรรม 3 ชั้น: Edge Device, Server/Broker, End-User

END-DEVICE
ชั้นปลายทาง: Sensor node, Actuator node, Wire/Wireless Sensor Networks ทำหน้าที่วัดค่า ตัดสินใจเบื้องต้น และส่งเฉพาะเหตุการณ์ที่สำคัญ
FOG / EDGE
ชั้นประมวลผลใกล้ขอบ: Fog/Edge Server, Server/Broker รวมข้อมูลหลายโหนด ลด latency และลดโหลดเครือข่ายก่อนส่งขึ้นคลาวด์
CLOUD
ชั้นคลาวด์: Cloud Server, Database, Analytics, Storage ประมวลผลภาพรวม จัดเก็บระยะยาว และให้บริการข้อมูลกับผู้ใช้
END-USER
ชั้นผู้ใช้: Mobile User, Web User, Machine-to-Machine รับการแจ้งเตือน ดูแดชบอร์ด และส่งคำสั่งกลับเข้าระบบ
ทำไมต้องกระจายการประมวลผล: ข้อจำกัดด้านพลังงานและแบนด์วิดท์ผลักให้ต้องประมวลผลใกล้เหตุการณ์ การตรวจจับเหตุการณ์ที่ edge ลดทั้งปริมาณข้อมูลในเครือข่ายและพลังงานวิทยุ เพราะการสื่อสารไร้สายกินไฟมากกว่าการคำนวณบนชิปเล็กๆ หลายเท่า

Cloud, Edge, Fog ต่างกันอย่างไร

  • Edge: ประมวลผลบนหรือใกล้โหนดมากที่สุด
  • Fog: ประมวลผลบนเซิร์ฟเวอร์ท้องถิ่นใกล้กลุ่มโหนด
  • Cloud: ประมวลผลรวมศูนย์บนเซิร์ฟเวอร์ขนาดใหญ่
7. Applications

แอปพลิเคชันจริงจากสไลด์ อ.ตั้ม

กลุ่มสิ่งที่ระบบทำ
Smart Industrialเฝ้ากระบวนการผลิต คุณภาพสินค้า และสภาพเครื่องจักร
Smart Buildingระบุตำแหน่งคนและสภาวะอาคาร คุม HVAC และไฟ เพื่อลดค่าใช้จ่าย
Smart Citiesเฝ้าจราจรคนและยานพาหนะ ผสานข้อมูลจากอาคารอัจฉริยะ
Vehiclesเครือข่ายเซนเซอร์ในรถ ปรับสมรรถนะ ลดเชื้อเพลิง และมลพิษ
Medical and Health Careเชื่อมเซนเซอร์ผู้ป่วยทั้งที่บ้าน รถพยาบาล คลินิก และโรงพยาบาล
8. Functional Requirements

บันไดความซับซ้อนของระบบ: จากเก็บข้อมูลสู่การควบคุม

Use case ช่วยกำหนดข้อกำหนดของระบบ IoT ไล่จากง่ายไปซับซ้อน:

1. Sensor Network (เก็บข้อมูล) 2. Alert System (แจ้งเตือน) 3. Analysis System (วิเคราะห์ต่อเนื่อง) 4. Reactive System (สั่งแอคชูเอเตอร์) 5. Control System (ควบคุมด้วย control law)
  • Sensor network: ทำหน้าที่เก็บข้อมูลจากเซนเซอร์อย่างเดียว
  • Alert system: วิเคราะห์แล้วส่งการแจ้งเตือนเมื่อเข้าเงื่อนไข
  • Analysis system: วิเคราะห์ต่อเนื่อง รายงานรายชั่วโมง รายวัน หรืออัปเดตสด
  • Reactive system: วิเคราะห์แล้วสั่งแอคชูเอเตอร์ แต่ยังไม่ใช่ control law เต็มรูปแบบ
  • Control system: ป้อนข้อมูลเซนเซอร์เข้าอัลกอริทึมควบคุม แล้วสร้างสัญญาณออกให้แอคชูเอเตอร์
9. Event-Driven Architecture

สถาปัตยกรรมขับเคลื่อนด้วยเหตุการณ์

หัวใจของ IoT คือ event-driven หรือ aperiodic sampling งานประมวลผลสัญญาณดั้งเดิมและระบบควบคุมมักสมมติว่ามีตัวอย่างเป็นคาบ แต่ time-series คงที่กินทั้งพลังงานที่โหนดและแบนด์วิดท์บนเครือข่ายมากเกินไป

Traditional periodic

Read Sensor Values 1, 2, ... N ตามคาบเวลา แม้ค่าจะไม่เปลี่ยนก็ยังส่ง เปลืองทั้งไฟและ bandwidth

Event-driven

อยู่ใน Main Task หรือ Idle เมื่อ Sensor Value เกิน threshold จึงส่งค่า ประหยัดพลังงานและเครือข่าย

ในที่นี้ event ถูกนิยามกว้างกว่านักจำลองระบบทั่วไป คือถือเป็น time-value sets และยอมรับ stuttering หรือการซ้ำค่าของเหตุการณ์เป็นส่วนหนึ่งของโมเดล เพราะระบบ IoT กระจายศูนย์

ข้อควรระวัง: ไม่ใช่ทุกแอปพลิเคชันเหมาะกับ aperiodic acquisition ต้องประเมินลักษณะสัญญาณจริงก่อนเลือกแบบแผนการสุ่มตัวอย่าง

11. Security and Privacy

ความปลอดภัยและความเป็นส่วนตัวในระบบกายภาพ

Security และ safety เป็นข้อกำหนดหลักของ IoT และไม่ใช่ปัญหาที่แยกจากกันอีกต่อไป เมื่อระบบคำนวณผสานกับระบบกายภาพ งานออกแบบความปลอดภัยของคอมพิวเตอร์ ต้องผสานกับงานออกแบบความปลอดภัยของระบบทางกายภาพ

  • ฮาร์ดแวร์หลายชิ้นมีฟีเจอร์ความปลอดภัยไม่เพียงพอ
  • ซอฟต์แวร์ออกแบบไม่ดี มีช่องโหว่และรหัสผ่านเริ่มต้น
  • โหนดไม่ปลอดภัยเพียงตัวเดียว สามารถทำลายความปลอดภัยของทั้งระบบ
  • อายุการใช้งานโหนดหลายปี ทำให้ฐานอุปกรณ์ที่ไม่ปลอดภัยอยู่ในสนามนาน
Privacy เกี่ยวข้องกับ security แต่ต้องออกแบบเพิ่มทุกชั้น ทั้ง application, network และ device ไม่ใช่แค่ป้องกันข้อมูลถูกขโมย แต่ต้องไม่ให้ข้อมูลที่ดูไม่ส่วนตัว ถูกใช้ลอนุมานข้อมูลที่ส่วนตัวกว่าได้
12. Mastery Checklist

เช็กลิสต์ประเมินความเข้าใจวิศวกรรม

1. เพราะอะไรจึงควรเรียก IoT system มากกว่า Internet of Things ลอยๆ
เพราะอุปกรณ์ส่วนใหญ่ถูกจัดเป็นระบบเฉพาะกิจเพื่อแอปพลิเคชันชุดหนึ่ง และต้องคำนึงถึงพลวัตของระบบทางกายภาพ ไม่ใช่การรวมอุปกรณ์อินเทอร์เน็ตแบบไร้จุดหมาย
2. ยกกายวิภาค IoT 4 องค์ประกอบ และบอกว่าองค์ประกอบใดเชื่อมกับโลกกายภาพ
Sensing, Processing, Actuating, Networking Sensing และ Actuating สัมผัสโลกกายภาพโดยตรง Processing ตัดสินใจ ส่วน Networking แลกเปลี่ยนข้อมูลกับระบบอื่น
3. อธิบายสถาปัตยกรรม 3 ชั้น และทำไมจึงต้องมี fog/edge
End-Device, Fog/Edge Server, Cloud และ End-User Fog/edge ลด latency และลดการส่งข้อมูลดิบ ซึ่งประหยัดทั้งแบนด์วิดท์และพลังงานวิทยุ
4. เปรียบเทียบ periodic sampling กับ event-driven ในแง่พลังงาน
Periodic อ่านและส่งเป็นคาบคงที่แม้ค่าไม่เปลี่ยน จึงกินไฟและ bandwidth มาก Event-driven ส่งเมื่อค่าเกินเงื่อนไข จึงประหยัดกว่า แต่ต้องออกแบบ threshold และยอมรับ aperiodic ได้
5. ยกตัวอย่าง Functional Requirements 5 ระดับจากง่ายไปยาก
Sensor network, Alert system, Analysis system, Reactive system, Control system ยิ่งสูงยิ่งต้องประมวลผลและโต้ตอบกับแอคชูเอเตอร์มากขึ้น
6. ทำไม security ของ IoT จึงผูกกับ safety ของระบบกายภาพ
เพราะการผสานระบบคำนวณกับระบบกายภาพทำให้ความล้มเหลวทางไซเบอร์ส่งผลต่อความปลอดภัยจริง จึงต้องออกแบบ safe physical system ร่วมกับ secure computer system
13. Mental Model

โมเดลความคิด 5 ข้อที่ต้องพกออกจากบทนี้

  1. IoT is a purpose-built system. ออกแบบเพื่อแอปพลิเคชันเฉพาะ ไม่ใช่กองอุปกรณ์ออนไลน์
  2. Physics matters. ต้องเคารพพลวัตของระบบกายภาพ ทั้งเวลา พลังงาน และความปลอดภัย
  3. Events beat time-series. เมื่อทรัพยากรจำกัด เหตุการณ์คุ้มกว่าการสุ่มตัวอย่างถี่ตลอดเวลา
  4. Compute near the signal. Edge/fog ลด latency และพลังงานวิทยุ ก่อนส่งขึ้นคลาวด์
  5. Security is part of safety. ระบบไซเบอร์ที่ไม่ปลอดภัยคือระบบกายภาพที่เสี่ยง
