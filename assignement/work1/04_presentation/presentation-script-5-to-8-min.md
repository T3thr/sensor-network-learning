# บทพูดนำเสนอ IoT-CAD — เป้าหมาย 6 นาที 10 วินาที

บทพูดนี้ตรงกับไฟล์สไลด์ 7 หน้าใน `03_slides` และอยู่ในช่วงเวลาที่กำหนด 5–8 นาที

## Slide 1 — เมื่อ sensor เตือน เราควรเชื่อหรือไม่? (0:00–0:35)

สวัสดีครับ วันนี้ผมนำเสนอบทความ IoT-CAD: Context-Aware Adaptive Anomaly Detection in IoT Systems Through Sensor Association จากงานประชุม IEEE/ACM ICCAD ปี 2020

ลองนึกถึงอาคารอัจฉริยะที่ sensor อุณหภูมิรายงานค่าสูงผิดปกติ คำถามสำคัญคือ เกิดไฟไหม้จริง หรือ sensor เสียหรือถูกโจมตี? ถ้าตีความผิด ระบบอาจพลาดเหตุอันตราย หรือแจ้งเตือนผิดจนผู้ใช้ไม่เชื่อระบบอีกต่อไป นี่คือปัญหาหลักของ paper นี้ครับ

## Slide 2 — EA กับ SDA ต่างกันอย่างไร? (0:35–1:20)

งานตรวจจับ anomaly ทั่วไปมักเรียนรู้ค่าปกติของ sensor แต่ละตัว แล้วถือว่าค่าที่ต่างจากที่ทำนายคือความผิดปกติ แต่วิธีนี้ยังไม่ตอบว่าต้นเหตุคือโลกจริงหรืออุปกรณ์

ผู้เขียนแบ่ง anomaly เป็นสองแบบ Environmental Anomaly หรือ EA คือเหตุการณ์จริงในสิ่งแวดล้อม เช่น ไฟ ซึ่งควรทำให้ sensor หลายชนิดที่สัมพันธ์กันเปลี่ยนพร้อมกัน ส่วน Sensing Device Anomaly หรือ SDA คือ sensor fault หรือ attack ซึ่งมักทำให้บางตัวขัดกับ pattern ของกลุ่ม แก่นของงานจึงคือการใช้บริบทจาก sensor หลายตัว ไม่ตัดสินจากตัวเดียวครับ

## Slide 3 — วิธีของ IoT-CAD (1:20–2:40)

กระบวนการมีสี่ขั้นหลัก

ขั้นแรก ระบบแปลงทิศทางการเปลี่ยนของข้อมูลเป็น binary fingerprint ถ้าค่าเปลี่ยนเกิน threshold ให้เป็น 1 ไม่เช่นนั้นเป็น 0 จึงเปรียบเทียบ sensor ต่างชนิดและต่างหน่วยได้

ขั้นที่สอง ใช้ Hamming distance วัดจำนวน bit ที่ต่างกัน แล้วจัดกลุ่ม sensor ที่มีประวัติการเปลี่ยนคล้ายกัน

ขั้นที่สาม แต่ละกลุ่มมี LSTM encoder-decoder ทำนายข้อมูลปกติ ความต่างระหว่างค่าจริงกับค่าที่สร้างใหม่เรียกว่า reconstruction error จากนั้น multivariate Gaussian ประเมินว่า error ชุดนี้มีโอกาสเกิดในภาวะปกติมากน้อยเพียงใด ถ้าโอกาสต่ำกว่า threshold จึงระบุเป็น anomaly

ขั้นสุดท้าย consensus ตรวจสมาชิกในกลุ่ม ถ้าหลาย sensor ผิดปกติสอดคล้องกันจะตีความเป็น EA แต่ถ้ามีเพียงบางตัวขัดกับกลุ่มจะเป็น SDA ระบบยัง retrain ด้วยข้อมูลปกติใหม่ และสร้าง model ใหม่เมื่อสมาชิก sensor เปลี่ยน จึงเรียกว่า adaptive ครับ

## Slide 4 — ทดลองกับระบบจริง (2:40–3:30)

ผู้เขียนสร้าง testbed จริง มี sensor 62 ตัว วัด 13 physical parameters เช่น อุณหภูมิ ความชื้น แสง การสั่นสะเทือน ก๊าซ และเสียง อุปกรณ์ส่วนใหญ่สื่อสารด้วย IEEE 802.15.4 ผ่าน Raspberry Pi gateway ไปยัง fog node ซึ่งเป็น laptop ระดับ Intel Core i5 และ RAM 8 GB

ข้อมูลปกติถูกเก็บ 8 วัน รวมประมาณ 2.3 ล้าน measurements การตรวจหนึ่งรอบใช้ 0.532 วินาทีใน testbed นี้ จึงแสดงความเป็นไปได้ของการประมวลผลใกล้แหล่งข้อมูล แต่ตัวเลขนี้ยังไม่ควรเหมารวมกับ hardware หรือเครือข่ายทุกแบบครับ

## Slide 5 — ผลลัพธ์: เด่นที่ precision แต่ recall ยังเป็นช่องว่าง (3:30–4:25)

จาก Table 2 IoT-CAD ได้ precision 92 เปอร์เซ็นต์ recall 56 เปอร์เซ็นต์ F0.5 เท่ากับ 81 และ F1 เท่ากับ 70 โดยมี precision, F0.5 และ F1 สูงสุดในชุดเปรียบเทียบ ขณะที่ ConvLSTM มี recall สูงกว่า คือ 95 เปอร์เซ็นต์

ดังนั้นห้ามเรียก 92 เปอร์เซ็นต์ว่า accuracy และห้ามสรุปว่า IoT-CAD ชนะทุก metric จุดแข็งคือเมื่อระบบแจ้งเตือน มักเป็นเหตุจริงมากกว่า baseline แต่ recall 56 เปอร์เซ็นต์หมายความว่าในชุดทดสอบยังพลาด anomaly จริงประมาณ 44 เปอร์เซ็นต์ นี่เป็น trade-off ที่สำคัญมากครับ

## Slide 6 — Contribution และ impact ในยุค AI (4:25–5:20)

Contribution แรกคือการนิยามโจทย์ให้ลึกกว่าการตอบว่า “ผิดปกติหรือไม่” โดยจำแนกต้นเหตุเป็น EA หรือ SDA

Contribution ที่สองคือ binary fingerprint และ sensor association ซึ่งค้นหาความสัมพันธ์ได้แม้ sensor คนละชนิดและคนละหน่วย

Contribution ที่สามคือการรวม LSTM, probabilistic threshold และ consensus เข้ากับ adaptive retraining บน fog computing และประเมินบน testbed หลาย modality

ในยุค AI งานนี้ยังมี impact เพราะระบบ AI ที่รับข้อมูลจากโลกจริงจะดีได้ไม่เกินคุณภาพของ sensor บทความจึงเป็นตัวอย่างของ trustworthy edge AI: ไม่เพียงทำนาย แต่ใช้บริบทตรวจความน่าเชื่อถือของข้อมูลก่อนนำไปตัดสินใจครับ

## Slide 7 — วิจารณ์และสรุป (5:20–6:10)

ข้อดีคือมีโจทย์ชัด ใช้ความสัมพันธ์ของ sensor เพื่อช่วยอธิบายต้นเหตุ ประเมินกับ testbed 62 ตัว และเปรียบเทียบ baseline หลายวิธี

ข้อจำกัดคือ recall เพียง 56 เปอร์เซ็นต์ anomaly ที่ใช้ประเมินเป็น synthetic ข้อมูลปกติมีเพียง 8 วัน และกลุ่มที่มี sensor น้อยกว่า 3 ตัวถูกตัดออกจากขั้นจำแนก EA/SDA นอกจากนี้ threat model ไม่ครอบคลุมผู้โจมตีที่ควบคุมหลาย sensor ให้โกหกสอดคล้องกัน และ retraining ก็อาจรับข้อมูลปนเปื้อนได้

สรุปคือ IoT-CAD แสดงว่า anomaly detection ที่น่าเชื่อถือไม่ควรเชื่อ sensor ตัวเดียว แต่ควรดูเวลา บริบท และฉันทามติของทั้งเครือข่าย งานต่อยอดที่น่าสนใจคือเพิ่มโมเดลที่ประเมิน uncertainty ป้องกัน model poisoning และทดสอบกับ anomaly จริงระยะยาว ขอบคุณครับ
