# รายงานตรวจหน้าเว็บ Paper 1

## ข้อสรุป

ยังคงใช้ IoT-CAD เป็นบทความหลัก ดังนั้นโครงสร้างหลักของ `paper-1/index.html` และ `paper-1/translation.html` ใช้ต่อได้ และตามคำขอครั้งนี้ยังไม่ได้แก้ไฟล์ HTML

## จุดที่ควรแก้ก่อนใช้เว็บเป็นแหล่งทบทวนฉบับสุดท้าย

1. ใน `translation.html` บริเวณคำอธิบายผล Table 2 ให้เปลี่ยนคำว่า “ชนะเลิศ” เป็น “ให้ precision, F0.5 และ F1 สูงสุดในชุดเปรียบเทียบของบทความ” เพราะ ConvLSTM ให้ recall สูงกว่า IoT-CAD
2. ประโยคที่อธิบายว่า false alarm ในโรงงาน “สร้างความเสียหายมากกว่า” เป็นข้อคิดเห็นที่บทความไม่ได้พิสูจน์ ควรเขียนว่า “ผู้เขียนให้ความสำคัญกับ precision และจึงรายงาน F0.5” แล้วแยกความเห็นเรื่องต้นทุน false alarm ไว้เป็นข้อวิจารณ์
3. ประโยค “งานวิจัยแรก” ควรเติมเงื่อนไขว่า “ผู้เขียนระบุว่าเป็นงานแรกเท่าที่ผู้เขียนทราบ ณ ปี 2020” เพื่อไม่ทำให้คำกล่าวเกินหลักฐาน
4. ประโยค “บรรลุ Precision 92% ใน 532ms” ควรระบุว่า 0.532 วินาทีเป็นเวลาตรวจหนึ่งรอบบน fog-node testbed ของบทความ ไม่ใช่คุณสมบัติที่รับประกันในทุกระบบ
5. ทุกตำแหน่งที่อธิบาย 92% ควรย้ำว่าเป็น precision ส่วน recall เท่ากับ 56% เพื่อป้องกันการตีความเป็น accuracy
6. เพิ่มข้อความใกล้ส่วนผลทดลองว่า anomaly ใน validation เป็น synthetic และข้อมูลปกติมาจาก testbed 8 วัน ข้อจำกัดนี้สำคัญต่อการประเมินความน่าเชื่อถือ
7. ในส่วน threat model ควรระบุชัดว่าผู้โจมตีที่ควบคุมหลายเซนเซอร์และรักษาความสัมพันธ์ของสัญญาณอาจหลบกลไก consensus ได้
8. บรรณานุกรม MCSOA ในส่วนบทความสำรองควรตรวจเลขหน้าให้ตรงกับ PDF/IEEE Xplore อีกครั้ง เพราะในไฟล์เดิมมีทั้ง 79–83 และ 80–84 ปรากฏต่างกัน จุดนี้ไม่กระทบงานส่ง IoT-CAD แต่ควรแก้ก่อนนำบทความสำรองไปใช้

## ข้อความแนะนำสำหรับส่วนความเกี่ยวข้องกับยุค AI

ใช้ข้อความสั้นว่า “คุณค่าของ IoT-CAD ในยุค AI อยู่ที่การตรวจความน่าเชื่อถือของข้อมูลกายภาพก่อนที่ AI จะใช้ข้อมูลนั้นตัดสินใจ ระบบเรียนทั้งความสัมพันธ์ตามเวลาและความสัมพันธ์ระหว่างเซนเซอร์ พร้อมแสดงข้อจำกัดด้าน concept drift และข้อมูลฝึกที่ปนเปื้อน”

หลีกเลี่ยงคำว่า “ทันสมัยที่สุด” เพราะแบบจำลองหลักเป็น LSTM จากงานปี 2020 และงานใหม่มี graph neural network, transformer และ federated learning แล้ว
