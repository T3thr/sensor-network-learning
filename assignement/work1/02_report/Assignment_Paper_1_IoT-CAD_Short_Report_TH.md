## บทคัดย่อฉบับแปลและสรุป

ระบบอินเทอร์เน็ตของสรรพสิ่งเชื่อมเซนเซอร์ เครือข่าย โปรแกรมควบคุม และสภาพแวดล้อมทางกายภาพเข้าด้วยกัน ความผิดพลาดของข้อมูลเซนเซอร์จึงส่งผลได้มากกว่าการแสดงค่าผิดบนหน้าจอ ในระบบควบคุมแบบวงปิด ค่าที่ผิดอาจทำให้ตัวควบคุมสั่งงานอุปกรณ์ผิด ส่วนระบบเฝ้าระวังอาจทำให้ผู้ใช้ตัดสินใจผิด ปัญหาสำคัญคือค่าที่ต่างจากพฤติกรรมปกติอาจเกิดจากเหตุจริงในสภาพแวดล้อม หรือเกิดจากเซนเซอร์เสียและการโจมตีข้อมูล วิธีตรวจจับที่พิจารณาเซนเซอร์ตัวเดียวมักแยกสองสาเหตุนี้ไม่ได้

บทความเสนอ IoT-CAD ซึ่งเป็นวิธีตรวจจับความผิดปกติแบบรับรู้บริบทและปรับตัวได้ ระบบสร้างบริบทจากความสัมพันธ์ของเซนเซอร์ต่างชนิดที่ตอบสนองต่อเหตุการณ์เดียวกัน แล้วจัดเซนเซอร์ที่มีรูปแบบการเปลี่ยนคล้ายกันให้อยู่ในกลุ่มเดียวกัน แบบจำลอง LSTM encoder-decoder เรียนรู้พฤติกรรมปกติของแต่ละกลุ่มและทำนายค่าถัดไป จากนั้นตัวประมาณแบบ multivariate Gaussian ประเมินความผิดปกติจากความคลาดเคลื่อนระหว่างค่าจริงกับค่าทำนาย เมื่อระบบพบความผิดปกติ กลไก consensus จะพิจารณาความสอดคล้องของสมาชิกในกลุ่มเพื่อจำแนกเหตุจากสภาพแวดล้อมและเหตุจากอุปกรณ์ตรวจวัด ระบบยังฝึกแบบจำลองใหม่เป็นระยะเพื่อรองรับการเปลี่ยนแปลงของสภาพแวดล้อมและโครงสร้างระบบ

ผู้เขียนทดลองกับเครือข่ายเซนเซอร์ 62 ตัวที่วัดตัวแปรทางกายภาพ 13 ชนิด เก็บข้อมูลปกติ 8 วัน รวมประมาณ 2.3 ล้านค่าการวัด แล้วประเมินด้วยข้อมูลที่เพิ่มความผิดปกติสังเคราะห์ IoT-CAD ให้ precision 92 เปอร์เซ็นต์ recall 56 เปอร์เซ็นต์ F0.5 81 เปอร์เซ็นต์ และ F1 70 เปอร์เซ็นต์ การตรวจจับหนึ่งรอบใช้เวลา 0.532 วินาทีบน fog node ในชุดทดลอง ผลแสดงว่าวิธีนี้ลดการแจ้งเตือนผิดได้ดี แต่ยังพลาดความผิดปกติจริงจำนวนมากและยังต้องทดสอบกับเหตุผิดปกติจริงที่หลากหลายกว่าเดิม

## 1 ที่มาและปัญหาวิจัย

บทความแบ่งความผิดปกติออกเป็นสองประเภท Environmental Anomaly หรือ EA หมายถึงการเปลี่ยนแปลงจริงในสภาพแวดล้อม เช่น ไฟไหม้ที่ทำให้อุณหภูมิ ความชื้น และแสงเปลี่ยน ส่วน Sensing Device Anomaly หรือ SDA หมายถึงเซนเซอร์หรือข้อมูลของเซนเซอร์ผิดปกติจากความเสียหาย การดัดแปลงอุปกรณ์ หรือการโจมตีช่องทางสื่อสาร ทั้งสองกรณีอาจทำให้ค่าของเซนเซอร์ออกนอกช่วงปกติเหมือนกัน จึงไม่สามารถระบุสาเหตุจากค่าของเซนเซอร์เพียงตัวเดียวได้

แนวคิดของงานตั้งอยู่บนข้อสังเกตว่าเหตุการณ์ทางกายภาพหนึ่งเหตุการณ์มักสร้างผลหลายรูปแบบ ตัวอย่างเช่น การเปิดประตูอาจทำให้สวิตช์แม่เหล็ก เซนเซอร์ตรวจจับบุคคล เซนเซอร์สั่น และไมโครโฟนเปลี่ยนพร้อมกัน หากสมาชิกที่เกี่ยวข้องส่วนใหญ่แสดงรูปแบบสอดคล้องกัน ระบบมีหลักฐานสนับสนุนว่าเกิดเหตุในสภาพแวดล้อมจริง แต่ถ้ามีเพียงบางตัวขัดกับกลุ่ม สาเหตุมีแนวโน้มมาจากอุปกรณ์หรือข้อมูลของอุปกรณ์นั้น

งานวิจัยต้องรับมือกับข้อมูลเซนเซอร์ที่ต่างชนิด ต่างหน่วย และต่างอัตราการสุ่มตัวอย่าง รวมทั้งการขาดข้อมูลความผิดปกติที่ติดป้ายกำกับไว้ล่วงหน้า นอกจากนี้ ระบบ IoT เปลี่ยนตามตำแหน่งอุปกรณ์ การเพิ่มหรือลดโหนด การปรับเฟิร์มแวร์ และการเปลี่ยนสภาพแวดล้อม แบบจำลองคงที่จึงเสื่อมประสิทธิภาพได้เมื่อเวลาผ่านไป

## 2 วิธีดำเนินการของ IoT-CAD

ขั้นแรก ระบบสร้าง binary fingerprint ให้เซนเซอร์แต่ละตัว โดยแบ่งข้อมูลเป็นช่วงเวลา คำนวณค่าเฉลี่ยของแต่ละช่วง แล้วเปรียบเทียบการเปลี่ยนแปลงสัมพัทธ์ระหว่างช่วงติดกัน หากการเปลี่ยนมากกว่าเกณฑ์จะบันทึกเป็น 1 มิฉะนั้นบันทึกเป็น 0 ลำดับบิตจึงแทนรูปแบบการเปลี่ยนแทนค่าดิบ วิธีนี้ช่วยให้เปรียบเทียบเซนเซอร์คนละหน่วยได้ เช่น อุณหภูมิองศาเซลเซียสกับความชื้นสัมพัทธ์

ขั้นที่สอง ระบบแบ่ง fingerprint เป็นลำดับย่อยและใช้ Hamming distance วัดจำนวนตำแหน่งบิตที่ต่างกัน จากนั้นทำ clustering สองระดับ ระดับแรกจัดกลุ่มรูปแบบย่อยที่คล้ายกัน ระดับที่สองจัดกลุ่มประวัติรูปแบบของเซนเซอร์ อัลกอริทึมปรับจำนวนกลุ่มอัตโนมัติและตัดกลุ่มที่มีสมาชิกน้อยกว่าสามตัว เพราะกลุ่มขนาดสองตัวไม่มีเสียงส่วนใหญ่เพียงพอสำหรับชี้ว่าตัวใดขัดแย้ง

ขั้นที่สาม ระบบสร้าง LSTM encoder-decoder แยกตามกลุ่มเซนเซอร์ LSTM เรียนความสัมพันธ์ตามเวลาและทำนายลำดับค่าปกติ ความต่างระหว่างค่าจริงกับค่าทำนายเรียกว่า reconstruction error งานนี้มอง error ของสมาชิกหลายตัวเป็นเวกเตอร์ แล้วประมาณการแจกแจงปกติหลายตัวแปรจากข้อมูลปกติ หากความน่าจะเป็นของ error ใหม่ต่ำกว่าเกณฑ์ alpha ระบบจะระบุว่าเป็นความผิดปกติ แม้งานเรียกวิธีหลักว่า unsupervised เพราะฝึกจากข้อมูลปกติ แต่ผู้เขียนใช้ข้อมูล validation ที่มีความผิดปกติสังเคราะห์เพื่อเลือก alpha ให้ได้ F-score สูงสุด จึงยังมีขั้นตอนปรับเกณฑ์ด้วยข้อมูลตัวอย่าง

ขั้นสุดท้าย consensus ตรวจความสอดคล้องภายในกลุ่มตลอดช่วงเวลา หากเซนเซอร์ที่สัมพันธ์กันเห็นความผิดปกติสอดคล้องกัน ระบบจัดเป็น EA หากมีเพียงหนึ่งตัวหรือบางตัวขัดกับสมาชิกส่วนใหญ่ ระบบจัดเป็น SDA และระบุต้นทางที่น่าสงสัย การตรวจเป็นช่วงเวลาช่วยรองรับความเฉื่อยทางกายภาพ เพราะเซนเซอร์แต่ละชนิดอาจตอบสนองต่อเหตุเดียวกันไม่พร้อมกันพอดี

IoT-CAD ทำงานบนสถาปัตยกรรม fog computing โดยนำการประมวลผลมาไว้ใกล้แหล่งข้อมูล ผู้เขียนสร้างแบบจำลองขนาดเล็กแยกตามกลุ่มเพื่อกระจายภาระระหว่าง fog nodes และลดการส่งข้อมูลดิบทั้งหมดไปยังคลาวด์ ระบบปรับตัวสองระดับ การปรับบางส่วนจะฝึก predictive model เพิ่มด้วยข้อมูลใหม่ที่ระบบมองว่าปกติ ส่วนการปรับสมบูรณ์จะสร้างความสัมพันธ์ของเซนเซอร์ แบบจำลอง และตัวประมาณใหม่เมื่อจำนวนอุปกรณ์เปลี่ยนหรือครบช่วงเวลาที่กำหนด

## 3 การทดลองและผลลัพธ์

ชุดทดลองประกอบด้วยเซนเซอร์ 62 ตัว ครอบคลุม 13 ตัวแปร เช่น อุณหภูมิ ความชื้น แสงที่มองเห็น แสงอินฟราเรด แรง การเอียง ความเร่ง การตรวจจับบุคคล สวิตช์แม่เหล็ก คาร์บอนไดออกไซด์ คาร์บอนมอนอกไซด์ ฝุ่น และเสียง โหนดกำลังต่ำสื่อสารด้วย IEEE 802.15.4 ผ่าน software-defined radio และ Raspberry Pi gateway แบบจำลองทำงานบนแล็ปท็อป Intel Core i5-6300HQ และ RAM 8 GB ซึ่งทำหน้าที่เป็น fog node

ผู้เขียนเก็บข้อมูลปกติ 8 วันประมาณ 2.3 ล้านค่าการวัด ผลเปรียบเทียบใน Table 2 รายงานว่า IoT-CAD มี precision 92 เปอร์เซ็นต์ สูงกว่า LSTM baseline ที่ 64 เปอร์เซ็นต์และ ConvLSTM baseline ที่ 51 เปอร์เซ็นต์ ส่วน One-Class SVM ให้ precision 89 เปอร์เซ็นต์ IoT-CAD มี F0.5 และ F1 สูงสุดที่ 81 และ 70 เปอร์เซ็นต์ตามลำดับ อย่างไรก็ตาม recall ของ IoT-CAD เท่ากับ 56 เปอร์เซ็นต์ ขณะที่ ConvLSTM ให้ recall 95 เปอร์เซ็นต์ ตัวเลขนี้สะท้อน trade-off ที่ IoT-CAD ให้ความสำคัญกับการลด false positive มากกว่าการตรวจพบความผิดปกติให้ครบทุกเหตุการณ์

การฝึก predictive model ครั้งแรกใช้เวลา 2,472.20 วินาที หรือประมาณ 41.2 นาที ขณะที่การตรวจข้อมูลใหม่หนึ่งรอบใช้เวลา 0.532 วินาที ผู้เขียนจึงเรียกระบบว่า real time สำหรับชุดทดลองนี้เท่านั้น การประเมินความทนต่อ noise แบบ Gaussian, pink และ uniform แสดงว่า precision ของทุกวิธีลดลงเมื่อพลังงาน noise สูงขึ้น แต่ IoT-CAD รักษา precision ได้ดีกว่าวิธีเปรียบเทียบ กรณีศึกษาจำลองไฟทำให้เซนเซอร์อุณหภูมิ ความชื้น และแสงที่อยู่ใกล้กันแสดงความผิดปกติร่วมกัน ระบบจึงจำแนกเป็น EA

## 4 Contribution ของงาน

Contribution แรกคืออัลกอริทึม sensor association ที่แปลงการเปลี่ยนแปลงของเซนเซอร์ต่างชนิดเป็น binary fingerprint แล้วจัดกลุ่มจากบริบทที่เรียนรู้จากข้อมูล วิธีนี้ไม่ต้องกำหนดความสัมพันธ์ของเซนเซอร์ทุกคู่ด้วยมือและไม่ติดกับหน่วยวัดของเซนเซอร์ชนิดใดชนิดหนึ่ง

Contribution ที่สองคือการเพิ่มขั้น consensus หลัง anomaly detector วิธีทั่วไปตอบเพียงว่าข้อมูลต่างจากปกติหรือไม่ แต่งานนี้ใช้ความสัมพันธ์ในกลุ่มเพื่อจำแนก EA และ SDA พร้อมระบุต้นทางที่น่าสงสัย ความสามารถนี้ทำให้ผลตรวจมีความหมายต่อการตัดสินใจมากขึ้น เช่น เหตุสิ่งแวดล้อมอาจต้องสั่งอพยพ ส่วน SDA อาจต้องตรวจอุปกรณ์หรือช่องทางสื่อสาร

Contribution ที่สามคือกลไกปรับแบบจำลองเมื่อสภาพแวดล้อมหรือโครงสร้างระบบเปลี่ยน งานทดลองแสดงว่าการไม่ปรับแบบจำลองทำให้ precision ลดลงมากในสถานการณ์ที่ค่าอุณหภูมิเปลี่ยน และแบบจำลองเดิมทำงานไม่ได้เมื่อจำนวนเซนเซอร์เปลี่ยน การปรับบางส่วนและการสร้างแบบจำลองใหม่ช่วยรักษาการทำงานภายใต้เงื่อนไขเหล่านี้

## 5 จุดเด่นของงาน

จุดเด่นสำคัญคือโจทย์วิจัยเชื่อม machine learning กับความหมายทางกายภาพของ sensor network ระบบใช้เซนเซอร์หลายตัวตรวจสอบกันแทนการเชื่อผลจากตัวเดียว จึงช่วยลด false alarm จากเหตุการณ์จริงในสภาพแวดล้อม นอกจากนี้ งานไม่ได้ประเมินเฉพาะโมเดล แต่สร้าง testbed ที่มีอุปกรณ์ 62 ตัวและเซนเซอร์หลายชนิด รายงาน precision, recall, F-score, ความทนต่อ noise และเวลาในการทำงาน ทำให้เห็นทั้งความแม่นยำและข้อจำกัดด้านการใช้งาน

สถาปัตยกรรมแบบกลุ่มยังเหมาะกับ fog computing เพราะสามารถวางแบบจำลองย่อยใกล้หน้างาน ลดการส่งข้อมูลดิบและลด latency แนวคิดนี้ยังเกี่ยวข้องกับยุค AI ปัจจุบัน เนื่องจากระบบ AI ที่รับข้อมูลจากโลกจริงต้องตรวจคุณภาพและความสอดคล้องของข้อมูลก่อนนำไปสรุปหรือสั่งการ แม้สถาปัตยกรรม LSTM จะไม่ใช่แบบจำลองใหม่ล่าสุด แต่ปัญหา sensor integrity, concept drift และการอธิบายสาเหตุของ anomaly ยังสำคัญต่อ edge AI, industrial IoT และ digital twin

## 6 จุดด้อยและข้อจำกัด

ข้อจำกัดที่ชัดที่สุดคือ recall 56 เปอร์เซ็นต์ ซึ่งหมายความว่าในชุดประเมิน ระบบตรวจพบความผิดปกติจริงเพียง 56 เปอร์เซ็นต์ ไม่ควรกล่าวว่า precision 92 เปอร์เซ็นต์หมายถึงระบบตรวจจับได้ถูกต้อง 92 เปอร์เซ็นต์ทุกกรณี สำหรับงานที่ false negative มีต้นทุนสูง เช่น ไฟไหม้หรือการควบคุมเครื่องจักร recall ระดับนี้อาจยังไม่เพียงพอและควรปรับ threshold ตามความเสี่ยงของระบบ

ผู้เขียนฝึกจากข้อมูลจริงที่เป็นภาวะปกติ แต่ประเมิน anomaly ด้วยข้อมูลสังเคราะห์เป็นหลัก ความผิดปกติจริงอาจมีรูปแบบละเอียดและเปลี่ยนตามอุปกรณ์มากกว่าที่การสังเคราะห์ครอบคลุม ระยะเก็บข้อมูล 8 วันและห้องทดลองเพียงแห่งเดียวยังไม่แสดงความสามารถข้ามฤดูกาล ข้ามสถานที่ หรือเมื่อระบบมีขนาดใหญ่ขึ้น

กลไก consensus ต้องพึ่งกลุ่มที่มีเซนเซอร์อย่างน้อยสามตัว เซนเซอร์เฉพาะทางที่ไม่มีอุปกรณ์สัมพันธ์กันอาจถูกตัดออก นอกจากนี้ threat model สมมติว่าผู้โจมตีไม่รู้ความสัมพันธ์และไม่สามารถควบคุมหลายเซนเซอร์ให้สร้างรูปแบบสอดคล้องกัน หากผู้โจมตีควบคุมสมาชิกส่วนใหญ่ในกลุ่ม consensus อาจตีความเหตุโจมตีเป็น EA ได้ การนำข้อมูลที่ระบบเชื่อว่าปกติกลับไปฝึกยังเปิดความเสี่ยงต่อ model poisoning หาก anomaly หลุดการตรวจจับ

## 7 ความเห็นและแนวทางต่อยอด

บทความนี้เหมาะกับนิสิตวิศวกรรมคอมพิวเตอร์ชั้นปีที่สี่ เพราะรวม sensor network, embedded communication, fog computing, time-series machine learning และ cybersecurity ไว้ในระบบเดียว แต่ยังมีขอบเขตชัดพอที่จะอธิบายภายใน 5 ถึง 8 นาที จุดที่ทำให้งานน่าสนใจในยุค AI ไม่ใช่การใช้ LSTM เพียงอย่างเดียว แต่คือการตรวจว่าข้อมูลกายภาพที่ป้อนให้ AI น่าเชื่อถือหรือไม่ และการใช้ความสัมพันธ์ระหว่างแหล่งข้อมูลเพื่ออธิบายสาเหตุของสัญญาณเตือน

หากต่อยอดเป็นโครงงาน ควรสร้างชุดข้อมูลที่มี sensor fault และการโจมตีจริง เปรียบเทียบ LSTM กับโมเดลกราฟหรือ transformer ที่เรียนความสัมพันธ์ระหว่างเซนเซอร์โดยตรง และรายงาน latency, หน่วยความจำ และพลังงานบน edge device จริง การประเมินควรแยกต้นทุน false negative ของเหตุอันตรายออกจาก false positive ของการแจ้งเตือนทั่วไป และควรทดสอบ coordinated attack กับกลไกป้องกันข้อมูลฝึกที่ปนเปื้อน
