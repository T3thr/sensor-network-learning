Federated Learning ทำงานอย่างไร (Section 2)

  1. Model initialisation: aggregator สร้างโมเดลตั้งต้น
  2. Local training: worker ฝึกด้วยข้อมูลของตนเอง ข้อมูลดิบไม่ออกจากเครื่อง
  3. Model update: worker ส่งเฉพาะพารามิเตอร์ที่เปลี่ยน
  4. Aggregation: aggregator รวมพารามิเตอร์ เช่น หาค่าเฉลี่ย
  5. Iteration: ทำขั้นที่ 2 ถึง 4 ซ้ำหลายรอบ

1

Leader Election

follower ที่ไม่ได้รับ heartbeat จนหมด randomised election timeout จะเปลี่ยนเป็น candidate เพิ่มหมายเลข term แล้วส่ง request_vote ผู้ที่ได้เสียงข้างมากของสมาชิกทั้งหมดเป็น leader

2

Heartbeat

leader ส่งสัญญาณเป็นระยะ เมื่อสัญญาณเงียบนานเกิน timeout จะเริ่มการเลือกตั้งรอบใหม่

3

Log Replication

leader ส่ง log entry ให้ follower และ commit เมื่อเสียงข้างมากตอบรับ ในบทความนี้ log คือ checkpoint ของพารามิเตอร์

ระดับสิ่งที่สำเนาผลเมื่อ aggregator ดับ
Level 0ไม่มีความคืบหน้าหาย
Level 1พารามิเตอร์บนดิสก์ของ aggregator เดิมต้องรอเครื่องเดิมกลับมา
Level 2ไม่มี แต่เลือกผู้นำใหม่ด้วย Raftฝึกใหม่ตั้งแต่ต้น
Level 3พารามิเตอร์ที่รวมแล้ว (บทความเลือก)ผู้นำใหม่ฝึกต่อจาก checkpoint
Level 4เพิ่มพารามิเตอร์ของ worker ทุกตัวครบที่สุด แต่ซ้ำซ้อนมาก

Self-Recovery Workflow (Section 5.3)

1

Check state

aggregator ตรวจสถานะที่สำเนาไว้: จำนวนรอบที่ฝึกแล้ว รอบที่เหลือ และพารามิเตอร์ล่าสุด

2

Checkpoint 3 จุด

หลังตั้งค่าพารามิเตอร์ หลังรวมผลการฝึก และหลังรวมผลการประเมิน โดยเขียนลง replicated key-value ของ PySyncObj ที่คัดลอกแบบ asynchronous

3

Aggregator alive?

worker ตรวจหลังทุกรอบการฝึกและการประเมิน ถ้า aggregator ไม่ตอบ ทุกโหนดกลับไปเลือกตั้งใหม่

4

Resume

aggregator คนใหม่ใช้พารามิเตอร์จาก checkpoint ล่าสุด ไม่ต้องเริ่มฝึกใหม่ตั้งแต่ต้น
