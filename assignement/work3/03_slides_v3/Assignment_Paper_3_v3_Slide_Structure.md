### หน้า 1: ปกและบริบท
กึ่งกลางหน้า เรียงจากบนลงล่าง: บรรทัดรายวิชา, ชื่อบทความภาษาอังกฤษ 34pt, ชื่อภาษาไทย 18pt, เส้นคั่นสีน้ำเงิน `#1E3A8A` หนา 3.5px กว้าง 2.2 นิ้ว, รายชื่อผู้แต่งและสังกัด, ชื่องานประชุมพร้อมหน้า, IEEE Doc ID และ DOI เป็นข้อความธรรมดาในบรรทัดเดียว, ชื่อผู้นำเสนอและรหัสนิสิต

### หน้า 2: ปัญหาและข้อจำกัดเดิม
การ์ดซ้าย "ทำไมการป้องกันแบบเดิมจึงไม่พอ" มี 4 ข้อ: parameterized query ใช้ไม่ได้ (Section VI-A), ข้อห้ามในพรอมต์ถูกหลบได้ด้วย "I am now user 2" (Finding 2), ภัยแบบอ้อมผ่านฐานข้อมูล (Finding 3), และบัญชีฐานข้อมูลของแชตบอตมีสิทธิ์เต็ม การ์ดขวาเป็นตัวอย่างจากแอปทดสอบ: ข้อความที่ผู้โจมตีพิมพ์, SQL `DROP TABLE users CASCADE` ที่ถูกรัน (ตัวสีแดง), ข้อความโจมตีแบบอ้อม RI.1 ที่ฝากไว้ในคำอธิบายประกาศงาน และตัวเลข 80,000 กับ 29,600 ดาวบน GitHub (Table I)

### หน้า 3: สถาปัตยกรรมและกลไกหลัก
ซ้ายคือภาพที่ 1 (Fig. 1, p. 1770) พร้อมคำบรรยาย 3 ขั้น ขวาคือตารางการโจมตี 7 รูปแบบจาก Table II แบ่งกลุ่มด้วยบรรทัดหัวกลุ่มสีเทา (U, RD, RI) คอลัมน์ SQL chain และ SQL agent และหมายเหตุเงื่อนไขการทดลอง (20 ครั้ง, gpt-3.5-turbo-0301, temperature 0)

### หน้า 4: การทำงานเชิงลึก
คอลัมน์ซ้ายบนคือภาพที่ 2 (Fig. 2, p. 1777) คอลัมน์ซ้ายล่างเป็นกล่องเปรียบเทียบก่อนและหลังของ Query rewriting ใน Hook b: `SELECT email FROM users` กลายเป็นคิวรีซ้อนที่ผูก `user_id = 5` จัดบรรทัดของ SQL ด้วยมือเพื่อไม่ให้ตัดกลางคำสั่ง คอลัมน์ขวาอธิบาย Hook a, b, c พร้อมเวลา 0.7 ms และ 1.87 ms และบรรทัดสรุปว่าไม่มีเทคนิคใดกันได้ครบ 7 แบบ (Table VII, Finding 12)

### หน้า 5: ผลการทดลองและตัวชี้วัด
ซ้ายคือภาพที่ 3 (Fig. 3, p. 1778) กราฟอัตราตรวจจับของ LLM guard 3 รุ่นเทียบ Rebuff พร้อมบรรทัดสภาพแวดล้อมทดสอบ ขวาคือกล่องสถิติ 3 กล่องขนาดเท่ากัน: 22 / 23 (Red Team, Table VI), 100% เทียบ 78% (ผลบวกลวง 0 จาก 150, ชุดขยาย 99.55%), และ 147.30 → 64.15 s (ลดลง 56.45%, Fig. 4)

### หน้า 6: จุดแข็ง จุดอ่อน และข้อจำกัด
สองการ์ดกว้างเท่ากัน การ์ดซ้าย "จุดแข็ง" 3 ข้อ: นิยามภัยใหม่อย่างเป็นระบบ, หลักฐานหลายชั้น, Defense in Depth การ์ดขวา "จุดอ่อนและข้อจำกัด" (หัวการ์ดและตัวเลขเป็นสีแดง) 3 ข้อ: ชุดประเมินเล็ก (60 และ 150 รายการ ไม่มี SD), ไม่ทดสอบ Adaptive Attacker, ขอบเขตผูกกับ LangChain 0.1.0 และไม่ใช้ Row-Level Security

### หน้า 7: บทสรุปและการประยุกต์ใช้งาน
การ์ดซ้าย "บทสรุปสำคัญ" 3 ข้อ: หมดยุค Parameterized Query เดี่ยวๆ, ชัยชนะของ Deterministic Rules เหนือ AI, และต้องใช้ Defense in Depth การ์ดขวา "การประยุกต์ใช้งานเชิงวิศวกรรม" 3 ข้อ: Enterprise Text-to-SQL Gateway, PostgreSQL Row-Level Security (RLS), และ AI Agent Tool-Calling Guardrails
